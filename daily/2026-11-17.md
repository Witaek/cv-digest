## TL;DR
- **Kornia 0.9.2 removes GPU→host syncs from its feature matchers.** LightGlue, ALIKED, DISK, XFeat, AdaLAM and LoFTR now read the device once per image (or not at all) where they used to read it once per tensor via `.item()` and boolean masks. Pipelines that run several matchers per frame on CUDA or MPS should see less waiting.
- **Kornia LoFTR linear attention now runs in float32 under FP16/autocast** and casts the result back. Before, its unnormalized sums could overflow float16 at ordinary coarse-grid sizes. If you run LoFTR in half precision, expect fewer NaN/inf matches.
- **AlbumentationsX 2.6.6: `Affine` (and `ShiftScaleRotate`) now handle image and masks at different resolutions** with `Compose(is_check_shapes=False)`. All targets share one rotation, scale and shear. `translate_percent` and `fit_output` use each target's own size. This extends yesterday's 2.6.4 change for flips and resizes.

## Models & releases

- **Kornia 0.9.2** — [PyPI](https://pypi.org/project/kornia/0.9.2/). Uploaded Nov 16, 19:21 UTC. No new models. Most of the code changes cut host syncs (see the deep read). Other changes:
  - **LoFTR, FP16:** `LinearAttention` now turns off the caller's autocast and computes Q, K, V in at least float32, then returns the query's dtype. The docstring says the unnormalized sums go past float16's range "at ordinary coarse-grid sizes" even when the output is representable. This replaces the old per-step tricks against FP16 overflow. Under TorchScript the autocast guard is skipped.
  - **ALIKED deformable conv:** the no-grad path now builds `grid_sample` coordinates straight from the offsets, which "keeps the kernel launches that bound small-image inference on CUDA few". `groups == 1` now uses a single `bmm` instead of `einsum`. A non-finite offset still gives NaN, as in the autograd path.
  - **LightGlueMatcher:** the keypoint scales and orientations are computed only for weights trained with them (`add_scale_ori`). The matcher now returns LightGlue's own `matches`/`scores` for the first image pair instead of rebuilding them from `matches0`.
  - **SO(3):** the left/right Jacobians no longer give NaN in double backward at the identity rotation (zero vector).
  - **`Boxes` from a list:** every tensor in the list is now checked for floating point, not just the first. With `raise_if_not_floating_point=False`, integer boxes are promoted to a common float dtype.
  - **Half-precision 3D crops** (`crop_by_transform_mat3d` path): boxes and the solved matrix stay in float32 through sampling, so rounding the matrix no longer moves the sampled voxels.
  - **MPS docs:** homography, fundamental-matrix and RANSAC docstrings now say which torch version each solver needs on MPS (e.g. `find_homography_dlt` with the default LU solver needs torch ≥ 2.10; weighted 8-point needs ≥ 2.14), or `PYTORCH_ENABLE_MPS_FALLBACK=1`.

## Today's deep read

**Fewer device reads in Kornia 0.9.2's matchers** — [kornia 0.9.2 sdist on PyPI](https://pypi.org/project/kornia/0.9.2/#files) (`kornia/core/ops.py`: `_copied_literal`; `feature/lightglue.py`, `feature/integrated.py`, `feature/disk/detector.py`, `feature/aliked/aliked.py`, `feature/xfeat.py`, `feature/adalam/utils.py`, `feature/loftr/utils/coarse_matching.py`).

- **What to read:**
  - **`_copied_literal`:** small constants like `[w - 1, h - 1]` used to be built with `torch.tensor(..., device=cuda)` or `new_tensor`, a blocking host→device copy that waits for all queued kernels. Now, in eager mode, they're built on the host and copied without blocking. Under `torch.compile` the old form stays, because Inductor treats it as a graph constant. The docstring says moving it made compiled CUDA `extract_patches_from_pyramid` 1.2–1.6× slower (torch 2.14, RTX 4090), and `laf.py` notes a 1.3× slowdown on MPS for one packed variant, so they kept three separate literals.
  - **Index, don't mask:** in LightGlue, XFeat and DISK, `x[valid]; y[valid]; z[valid]` (one device read per tensor) became one `torch.nonzero(valid)` followed by gathers. DISK's top-n now places kept maxima with a `cumsum` + `scatter_`, with no read at all.
  - **ALIKED border suppression:** a Python loop with two `.item()` calls per image became one broadcast comparison on the device, including the negative-start case for images smaller than the NMS radius.
  - **AdaLAM:** the pair-index sequence is now `torch.tril_indices(...)[:, :k]`, whose size depends only on Python ints, replacing `repeat_interleave` + `max().item()`.
  - **LoFTR coarse matching:** the `mconf != 0` filter now runs only in training (where ground-truth pads have `mconf == 0`). At inference every match already has a positive score, so the filter and its sync are skipped.
- **Why it matters:** each sync stalls the CPU until the GPU drains its queue, so the next kernels can't be queued ahead of time. In a matcher with many small kernels on small images, those stalls, not the math, set the latency. The README cites an earlier change of the same kind ([#6501](https://github.com/kornia/kornia/pull/6501)) that made `match_smnn` 1.4–1.9× faster on CUDA. This release doesn't publish new end-to-end numbers for these matchers, so measure your own.
- **How it could apply to you:**
  - **Profile your own pipeline for the same pattern.** In Nsight Systems or `torch.profiler`, look for `cudaStreamSynchronize`/`aten::item`/`aten::nonzero` between kernels. `torch.cuda.set_sync_debug_mode("warn")` flags each one in eager code. Post-processing (score thresholds, NMS outputs, `boxes[scores > t]`) is the usual culprit.
  - **Copy the fixes:** make one `nonzero` and gather the rest; build constants with a non-blocking copy from pinned memory, or as Python scalars; replace `if tensor:` checks with `torch.where`.
  - **Note the compile caveat:** under `torch.compile`, a device-side literal can be faster than a host copy, so check both modes before choosing.
  - **Check LightGlueMatcher callers:** it now returns LightGlue's own `matches`/`scores` for the first pair. For the single image pair it is built for, the result should not change. If you ever passed a batch of pairs through it, check the output.
