## TL;DR
- **Triton 3.9.0 is out, with breaking changes.** Block pointers are gone: `tl.make_block_ptr` now raises, so port those kernels to tensor descriptors. It also drops Python 3.10 and adds Cluster Launch Control on SM100+, up to 40x faster batched MMAv2 dots and a bundled CUDA 13 ptxas for Hopper and newer.
- **Ultralytics 8.4.191 moves the RKNN INT8 box decode onto the CPU.** INT8 export for Rockchip NPUs now covers detect, segment, pose and OBB. The final decode runs in float in a separate `tail.onnx`, to fix accuracy loss. Re-export INT8 models made with older versions. Accuracy has been checked only in the RKNN simulator, not on Rockchip hardware.
- **New papers: 50 FPS camera-LiDAR 3D detection and mixed-label instance segmentation.** FastBEVFusion does camera-LiDAR fusion without depth estimation and claims more than 50 FPS on nuScenes. MixSIS (BMVC '26) trains instance segmentation from a COCO mix of masks, boxes, points and image labels. It reaches 32.3 mask mAP on its main mix, and the weights are released.

## Top papers

- **FastBEVFusion: Simple Multi-Modal Fusion for 3D Object Detection at 50 FPS** — [link](https://arxiv.org/abs/2610.37153). From Tom Sanitz, Emre Gülsoylu, Simone Frintrop and Christian Wilms (University of Hamburg).
  - **What it does:** camera-LiDAR fusion into a bird's-eye view (BEV) for 3D detection, without the per-pixel depth estimation that BEVFusion-style pipelines use to lift camera features.
  - **How it works:** a "semi-aligned" BEV representation of the camera features, fused with LiDAR through lightweight dynamic cross-attention.
  - **Numbers:** an aggregator's summary says it beats earlier real-time systems on nuScenes at more than 50 FPS and is robust to calibration error. The abstract was rate-limited, so we don't have the mAP/NDS figures or the GPU. No code is linked yet.
  - **Why it matters:** depth estimation is usually the bottleneck in a fusion model. A fusion head that skips it and tolerates calibration drift is attractive for vehicles and robots with shifting extrinsics. Check the tables for the hardware before comparing with BEVFusion latency.
- **MixSIS: Mixed-supervised instance segmentation** — [link](https://arxiv.org/abs/2610.37138), [code + weights](https://github.com/chwilms/MixSIS). Same Hamburg group, BMVC '26.
  - **The setting:** each object in an image can have a different label type: a mask, a box, points or only an image-level class. Three random mixes of COCO train2017 define the benchmark.
  - **Baseline (AnnsMixer):** CAMs and SAM, prompted with the boxes and points, turn the weak labels into pseudo-masks. These are merged with the real masks, and a standard Mask R-CNN is trained on the result.
  - **Numbers (COCO mask mAP):** 32.3 / 29.5 / 26.6 on mixes 1–3. For comparison, the same pipeline scores 34.5 with only boxes, 26.2 with only points and 22.0 with only image labels. Trained Mask R-CNN weights and pseudo-masks are released under GPL-3.0.
  - **Why it matters:** this matches how labelling budgets look in practice: a few full masks plus cheap boxes or clicks for the rest. The paper also has case studies on annotation time.
- **XTrack: Repurposing Video Diffusion Transformers for Cross-View Temporal Object Correspondence** — [link](https://arxiv.org/abs/2610.37633), [project](https://cvlab-kaist.github.io/XTrack/), [repo](https://github.com/cvlab-kaist/XTrack). From Siyoon Jin, …, Seungryong Kim (KAIST). NeurIPS 2026.
  - **The task:** given a mask of an object in the first frame of one camera (e.g. an egocentric headset), track the same object in both that camera and a second one (e.g. a third-person view) for the whole video.
  - **How it works:**
    - A pretrained video DiT, fine-tuned with flow matching, outputs mask latents instead of RGB. Both views share one token sequence, so the same attention handles matching across views and tracking over time.
    - Hard-negative conditioning and an object-centered crop help it tell apart lookalike objects and find small ones.
    - Ego-Exo4D's 1 FPS masks are densified to 30 FPS pseudo-labels with SAM2, then checked with VGGT for cross-view geometry and with DINOv3 for semantics.
  - **Numbers:** the project page and README claim only "highly competitive" results, with no figures. The repo has no code or weights yet.
  - **Why it matters:** the pseudo-label pipeline (SAM2 propagation plus geometry and feature checks) can be reused on any sparsely labelled multi-camera dataset.
- **FVQ: Can Discrete Tokens Serve as Semantically Lossless Representations of Visual Signals?** — [link](https://arxiv.org/abs/2610.37662), [code + weights](https://github.com/hustvl/FVQ). From Jialv Zou, …, Xinggang Wang (HUST).
  - **The idea:** reconstruction error is a poor guide to how much meaning discrete visual tokens keep. One quantizer variant has 9.1x the MSE of plain VQ yet scores 9.5 points higher on understanding tasks.
  - **The tokenizer:** 16 parallel codebooks quantize complementary projections of frozen vision-encoder features.
  - **Numbers:** FVQ-8B (Qwen3-8B with the tokenizer on the Qwen3 ViT) scores 77.4 on MathVista, 95.4 on DocVQA and 867 on OCRBench. Qwen3-VL-8B, which uses continuous visual features, scores 896 on OCRBench.
  - **Relevance:** this is VLM work. It matters for perception only if you plan to put discrete visual tokens in a pipeline. The tokenizer and the 8B model are released under Apache-2.0.
- **MvT: Event-based Multi-view Projection for Multiple Object Tracking** — [link](https://arxiv.org/abs/2610.37309), [TIP page](https://signalprocessingsociety.org/publications-resources/ieee-transactions-image-processing/2026/09/mvt-event-based-multi-view-projection-multiple-object-tracking). From Muxi Zha, …, Laurent Kneip. Published in IEEE TIP, September 2026.
  - **How it works:** a training-free multi-object tracker for event cameras. It projects the event stream into three spatio-temporal views, which disambiguates trajectories that cross or sit close together. Results are fused in 3D, and tracklets are linked by an optimization step.
  - **Numbers:** the authors claim it beats both learned and non-learned trackers on four datasets, including their new Small Objects Dataset. The page gives no figures. Code is said to be public.
  - **Companion paper:** the same group has a [hierarchical sparse graph method](https://arxiv.org/abs/2610.37321) for event-based assignment (unread).

## Models & releases

- **Ultralytics 8.4.191** — [notes via Renovate PR](https://github.com/chrisns/poormanYoloCam/pull/307). Released Oct 27.
  - **RKNN INT8 decode on the host (#26904):** INT8 export now covers detection, segmentation, pose and OBB. The NPU runs the model up to the head's final convolutions, and a separate `tail.onnx` decodes boxes in float on the CPU, using ONNX Runtime. FP16-capable targets keep high-error layers in float through `auto_hybrid`. Accuracy was checked only in the RKNN simulator.
  - **Training:** foreground anchors for the segmentation loss are now found once per batch (#26914). Losses are unchanged, and Ultralytics reports "modest" speedups on a T4 with no figures.
  - **Tracking:** OC-SORT now measures an object's direction of motion over its last `delta_t` frames (#26912), so associations are less sensitive to box jitter.
- **supervision 0.31.3** — [changelog](https://supervision.roboflow.com/latest/changelog/). Released today.
  - **Datasets:** `as_yolo` now skips crowd annotations and merges multi-part masks into one polygon by default (#2786). Check exported YOLO-seg labels if you rely on this.
  - **Keypoints:** `KeyPoints.as_detections` / `with_nms` now use only x/y coordinates (#2817).
  - **Fixes:** the NumPy fallbacks now match OpenCV rendering more closely, and grayscale scenes work in two more annotators.
- **Release check (PyPI):** unchanged since yesterday for torch 2.14.1, torchvision 0.29.1, timm 1.0.30, rfdetr 1.11.2, Roboflow Inference 1.8.3, transformers 5.21.0, ONNX Runtime 1.31.1, TensorRT 11.4.0.106, OpenVINO 2026.4.1, LiteRT 2.3.0, ExecuTorch 1.5.1, Model Optimizer 0.47.0, torchao 0.18.0 and flash-attn 2.8.3.post2.

## Edge & deployment

- **What the Ultralytics RKNN change means for deployment:** an INT8 RKNN model is now two pieces: the `.rknn` model plus `tail.onnx`. If your C++ or Android runtime only loads the `.rknn`, you must run `tail.onnx` too or reimplement its decode. Models exported as INT8 with earlier versions can scale coordinates wrongly, per the notes, so re-export them. Measure mAP on the device before shipping, since Ultralytics hasn't yet.

## GPU / CUDA / PyTorch

- **Triton 3.9.0** — [release notes](https://github.com/triton-lang/triton/releases/tag/v3.9.0). Released Oct 27.
  - **Breaking changes:**
    - Block pointers are removed: `tl.make_block_ptr` raises `NotImplementedError` and `tl.advance` is gone. Use tensor descriptors (#10833).
    - `cache_modifier`, `eviction_policy` and `volatile` on `tl.load`/`tl.store` are now keyword-only.
    - Python scalars no longer widen results of min, max and comparisons, and division of sub-32-bit floats returns float32 (#10883).
    - Python 3.10 and AMD RDNA1/2 (gfx10) are dropped.
  - **NVIDIA:**
    - Cluster Launch Control on SM100+ (`clc=True`, #11124).
    - Batched MMAv2 dots up to 40x faster (#11822).
    - Bundled CUDA 13 ptxas (13.4.59) for sm_90 and newer (#12035). This changes which env var sets the Hopper ptxas: sm_90 now uses `TRITON_PTXAS_BLACKWELL_PATH`.
  - **Coming in 3.10:** implicit FMA fusion will be off by default. Set `TRITON_DEFAULT_FP_FUSION=0` now to check whether your kernels' numerics change.
  - **Action:** custom kernels for attention, NMS or deformable sampling that use block pointers will break on upgrade. Pin `triton<3.9` until they are ported.
- **CUDA 13.4 memory-enforced GPU sharing in Kubernetes** — [NVIDIA blog](https://developer.nvidia.com/blog/memory-enforced-gpu-sharing-in-kubernetes-with-nvidia-cuda-13-4/). Oct 27.
  - **What it does:** CUDA 13.4 can hold each process on a shared GPU to a fixed memory limit. An allocation past the limit fails as if the GPU were smaller, and the application needs no changes.
  - **Kubernetes setup:** an open-source GPU Fractioning Operator runs this through MPS, with KAI Scheduler ≥ v0.18 setting per-pod limits. Pods either take turns on the GPU (time-slicing, separate error domains) or split its compute units (sm-sharing, one shared error domain).
  - **Why it matters:** several small inference services can share one GPU with hard memory limits, without MIG.

## Today's deep read

**MixSIS** — [paper](https://arxiv.org/abs/2610.37138), [code + weights](https://github.com/chwilms/MixSIS).

- **What to read:**
  - **AnnsMixer:** how SAM is prompted from boxes versus points, and how pseudo-masks that disagree with CAMs are filtered before Mask R-CNN training.
  - **The case studies:** the annotation-time study, which shows how much mask quality each cheaper label type buys per hour of labelling. Also, whether a mix beats boxes-only at the same cost.
- **How it could apply to you:**
  - **Plan your labelling budget:** if you are paying for polygon masks on everything, run your current set through the MixSIS mix files as a template. Keep full masks for a subset, downgrade the rest to boxes or clicks, and see how much of the gap AnnsMixer's pseudo-masks close on your validation set.
  - **Swap in your own detector:** the recipe doesn't depend on the detector. Generate the pseudo-masks once, then train YOLO-seg or RT-DETR-seg on them instead of Mask R-CNN.
