Validation stays at 0.7, so mAP doesn't change. But if you never set `iou=`, you'll now get fewer overlapping boxes at inference, and models exported with NMS built in will behave differently. ## Models & releases

- **Ultralytics 8.4.208** — [PyPI](https://pypi.org/project/ultralytics/8.4.208/). Uploaded Nov 8, 14:54 UTC. From the 8.4.207→8.4.208 sdist diff:
  - **New NMS IoU defaults.** `iou` in `default.yaml` is now empty by default, and each mode fills in its own value:
    - **Predict and export:** 0.5 (`PREDICT_IOU`), down from 0.7.
    - **Validation:** still 0.7 ("highest mAP").
    - **SAM and FastSAM:** keep 0.7, because their masks are nested and single-class.
    - **Integrations follow the new constant:** Core ML's built-in NMS (it was 0.45), the IMX export (0.7), `auto_annotate` (0.45), Solutions and the Streamlit app.
  - **The confusion matrix now matches at 0.5 IoU** (it was 0.45), the same criterion as mAP50. Confusion matrices from older runs aren't directly comparable.
  - **YOLOE with visual prompts** now defaults to `conf=0.05`.
  - **Class colors:** add `colors:` to the dataset YAML. A malformed list is ignored as a whole, with a single warning. The colors are attached to the model when training, written to export metadata, and read back by `AutoBackend`. Label text now switches between navy and white based on the background's brightness, instead of using two hard-coded color lists. Pose limb and keypoint colors were reordered too, so pose plots will look different.
  - **Faster DDP with gradient accumulation:** when `accumulate > 1` and the model isn't compiled, steps that don't update the weights now run under `no_sync()`. That means gradients are all-reduced only on optimizer steps, not on every micro-batch.
- **Release check (PyPI):** unchanged for RF-DETR 1.12.0, torch 2.15.0, torchvision 0.29.2, timm 1.0.31, supervision 0.31.5, transformers 5.22.2, SAHI 0.14.0, ONNX Runtime 1.31.1, TensorRT 11.4.0.106, OpenVINO 2026.4.1, LiteRT 2.3.0, ExecuTorch 1.6.0, Triton 3.9.0, torchao 0.18.0, flash-attn 2.8.3.post2, Kornia 0.9.0, cuDNN 9.28.1.4 and DALI 2.4.0. Roboflow Inference has a pre-release, 1.8.5rc1 (Nov 5); 1.8.4 is still the stable version. YOLO27 weights are still not out.

## Edge & deployment

- **TensorRT FP16 export: Ultralytics' ModelOpt AutoCast path now keeps the box post-processing in FP16** (8.4.208). `data_max` is raised from AutoCast's default of 512 to the FP16 maximum. The code comment says the 512 default "keeps pixel-space box post-processing in FP32". **Caution:** FP16 can only store pixel coordinates between 512 and 1024 in steps of 0.5 px, and above 1024 in steps of 1 px. That's harmless at `imgsz=640`, but check box precision if you export at 1280 or more.
- **Re-check exported models with NMS built in.** With 8.4.208, a re-export with no `iou=` bakes in 0.5 (it was 0.7). On Core ML it moves from 0.45 to 0.5. So two engines built from the same weights a week apart can disagree. Pass `iou=` explicitly at export.
- **NVIDIA Model Optimizer, coming in 0.49.0** — [CHANGELOG on main](https://github.com/NVIDIA/Model-Optimizer/blob/main/CHANGELOG.rst). Not released yet. It includes two ONNX quantization fixes that matter for vision models:
  - The default `concat_elimination` pass no longer crashes in calibration when one input to a `Concat` is a constant, such as a ViT's class token.
  - A rank-0 constant no longer gets a per-tensor Q/DQ pair, which TensorRT's parser rejected.
  - On Linux x86-64, the ONNX extra will default to ONNX Runtime 1.30.x and CUDA 13 packages.
  - Separately, a 0.47.1 patch was uploaded to PyPI on Nov 6. It has no changelog entry.

## Today's deep read

**The NMS IoU change in Ultralytics 8.4.208** — [8.4.208 sdist on PyPI](https://pypi.org/project/ultralytics/8.4.208/#files).

- **What to read:**
  - `PREDICT_IOU` in `ultralytics/utils/__init__.py`.
  - How `BasePredictor.__init__` and `stream_inference` fill in `default_iou`. A reused predictor resets to it on every call.
  - The validator's separate 0.7 default.
  - `Exporter.__init__`, which now applies the predict default to NMS that's built into exported models.
- **Why it matters:** NMS IoU is a setting most people never touch. 0.7 keeps boxes that overlap heavily, which helps in crowds but leaves duplicates elsewhere. 0.5 removes more of them. Anything counted downstream will shift: line-crossing counts, track IDs, per-frame alerts. mAP won't show it, because validation still runs at 0.7.
- **How it could apply to you:**
  - **Pin it:** set `iou=` explicitly in predict calls and export commands, or you'll get the change silently on your next `pip install -U`.
  - **Measure it on your own footage:** run your eval clips at 0.5 and 0.7 and compare duplicates against missed detections in crowded scenes. People in queues and stacked parcels are where 0.5 starts suppressing true positives.
  - **NMS-free models don't care:** if you deploy end-to-end models like YOLO26 or RF-DETR, there's no NMS and the threshold doesn't apply. But 8.4.208 still changes the default for any NMS-based checkpoint you serve alongside them.
