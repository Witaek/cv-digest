## TL;DR
- **supervision 0.31.6 makes `Detections.from_transformers` work with zero-shot detectors and RF-DETR segmentation.** Grounding DINO results used to crash; now they load with their matched phrases as class names. OWL-ViT, OWLv2 and OmDet-Turbo take their class names from `text_labels`. RF-DETR binary masks are now matched to the right segments.
- **Counting fixes for tracking pipelines.** `DetectionsSmoother` no longer averages unconfirmed tracks (negative `tracker_id`) into a single "phantom" box. `PolygonZone` no longer counts an anchor just outside the top or left edge as being inside. Line and zone counts can shift after you upgrade.
- **Pose class IDs are fixed.** `KeyPoints.from_transformers` now gives every pose class `0`, not `0..N-1`. In the changelog's example, the old numbering dragged keypoint mAP for four perfect ViTPose poses down to 0.257 instead of 1.0. `from_yolo_nas` now keeps each pose's score, so `with_nms` works.

## Models & releases

- **supervision 0.31.6** — [PyPI](https://pypi.org/project/supervision/0.31.6/), [changelog on develop](https://github.com/roboflow/supervision/blob/develop/docs/changelog.md). Uploaded Nov 10, 11:13 UTC. The changelog still lists these under "Unreleased", but the 0.31.5→0.31.6 sdist diff contains them.
  - **Zero-shot detection from Transformers.** Pass the output of `post_process_grounded_object_detection` to `from_transformers`:
    - **Grounding DINO:** gives phrases rather than query indices, so `class_id` is `None` and the phrases go into `class_name`. Before, it raised `AttributeError: 'list' object has no attribute 'cpu'`.
    - **OWL-ViT, OWLv2 and OmDet-Turbo:** `class_id` is the index of the matched text query, and class names now come from `text_labels` instead of `id2label`.
  - **RF-DETR and Mask2Former segmentation with `return_binary_maps=True`.** Binary maps are now paired with `segments_info` by position, not indexed by segment ID. RF-DETR numbers segments from 1, so the old code raised `IndexError` (Mask2Former and MaskFormer number from 0). An empty `(0, H, W)` stack now gives empty masks instead of raising. The docs now recommend the official `rfdetr` package, whose `predict()` returns `Detections` directly.
  - **Keypoints:**
    - `KeyPoints.from_transformers` gives every pose class ID `0`. With the old `0..N-1` numbering, each person counted as a separate class. That broke class-aware metrics, and `EdgeAnnotator` with per-class `edges` raised on the second person.
    - `KeyPoints.from_yolo_nas` keeps the pose score as `detection_confidence`, so `with_nms` and `as_detections` now work on YOLO-NAS poses.
    - `KeyPoints.empty()` now holds empty `class_id` and confidence arrays instead of `None`, so filters like `kp[kp.detection_confidence > 0.5]` no longer raise on frames with no poses.
  - **bfloat16:** `Classifications.from_timm` and `from_clip` now accept bf16 outputs, such as from autocast inference, and return float32 probabilities. Before, `.numpy()` raised on bf16.
  - **Smaller fixes:**
    - `xywh_to_xyxy` no longer overflows small integer types. A `uint8` box `[200, 20, 100, 40]` used to wrap its right edge to 44.
    - `LabelAnnotator` now draws labels like `0` and `False` as text instead of empty boxes.
    - `ColorPalette.from_matplotlib` rounds channels instead of truncating them, so some colors move by one level.
    - `JSONSink` no longer hides an exception raised inside its `with` block.
- **Release check (PyPI):** unchanged for Ultralytics 8.4.208, RF-DETR 1.12.0, torch 2.15.0, torchvision 0.29.2, timm 1.0.31, transformers 5.22.2, SAHI 0.14.0, ONNX Runtime 1.31.1, TensorRT 11.4.0.106, OpenVINO 2026.4.1, LiteRT 2.3.0, ExecuTorch 1.6.0, Triton 3.9.0, torchao 0.18.0, flash-attn 2.8.3.post2, Kornia 0.9.0, Model Optimizer 0.48.0 (0.49.0 still unreleased), cuDNN 9.28.1.4, DALI 2.4.0 and cuda-python 13.5.0. ## Edge & deployment

- **supervision without OpenCV now matches OpenCV more closely** (0.31.6). This matters for slim containers and edge images that skip `opencv-python`:
  - **Polygon order:** `mask_to_polygons` now returns polygons in OpenCV's `RETR_TREE` order (each outline, then its holes; siblings last-found first). Before, the NumPy fallback returned them in raster order, so code that took `polygons[0]` could get a different shape depending on whether OpenCV was installed.
  - **Heat-map colors:** the HSV→BGR fallback now copies OpenCV's float32 math and its 32-pixel AVX2 rounding. `HeatMapAnnotator` colors match OpenCV's x86-64 wheels, apart from occasional one-level differences.
  - **Image writes:** 16-bit grayscale, BGR and BGRA PNGs keep 16 bits without OpenCV; there is a hand-written encoder, because Pillow can't write 16-bit color PNGs. JPEG, BMP and WebP get a saturated 8-bit copy, the way `cv2.imwrite` does it. Before, these writes raised `TypeError`.
  - **Grayscale and transparent images:** `RichLabelAnnotator`, `draw_image` and palette-mode Pillow images now work on grayscale, BGRA and `P`/`PA` scenes instead of raising or drawing the wrong colors.

## Today's deep read

**`DetectionsSmoother` and `PolygonZone` in supervision 0.31.6** — [0.31.6 sdist on PyPI](https://pypi.org/project/supervision/0.31.6/#files), [changelog](https://github.com/roboflow/supervision/blob/develop/docs/changelog.md).

- **What to read:**
  - `DetectionsSmoother.update_with_detections` in `detection/tools/smoother.py`. Look at the `unconfirmed = tracker_ids < 0` mask and how the untouched rows are merged back at the end.
  - `PolygonZone.trigger` in `detection/tools/polygon_zone.py`. The bounds check now runs *before* rounding, so an anchor at x = −0.4 no longer rounds onto pixel 0.
- **Why it matters:** some trackers give every unconfirmed detection the same negative ID. The old smoother put all of them in one history and averaged them. The changelog's example: two objects at x = 0 and x = 100 came back as one box at x = 50. In a crowded scene, that means fake boxes and too few objects for zones and line counters downstream. The zone fix matters most with camera-mapped anchors and zones drawn against the frame edge.
- **How it could apply to you:**
  - **Re-baseline your counts.** Before you upgrade, replay a few recorded clips through your counting pipeline on 0.31.5 and on 0.31.6, and diff the per-frame zone counts. Expect changes in crowds and near the frame edges.
  - **Check the output order.** Unconfirmed detections now come back unchanged, *after* the smoothed tracks, so the output order differs from the input. Code that zipped smoother output with per-detection labels by index needs to look rows up by `tracker_id` instead.
  - **Oriented boxes:** if some tracks lose their oriented corners during smoothing, every track in that frame falls back to axis-aligned corners. Before, the merge raised an error. Downstream OBB geometry may be coarser on those frames.
