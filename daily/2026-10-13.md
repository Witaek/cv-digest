## Top papers

- **FOCUS: Fine-Grained Open-Vocabulary Change Detection for Uncertainty-Aware Semi-Static Scenes** — [link](https://arxiv.org/abs/2610.05639). *(Early October, title only.)* Per its title, it detects fine-grained changes in scenes that are mostly static, using open-vocabulary categories and modeling uncertainty. It is relevant to inspection and monitoring systems, which have to flag what moved or appeared without a fixed class list.
- **Retrospective Open-Vocabulary Memory for Long-Term Object Search** — [link](https://arxiv.org/abs/2610.00330). *(Oct 1, title only.)* A memory of open-vocabulary detections that can be queried after the fact, so a robot can find objects it saw earlier. It sits close to the ActiveLang 3D mapping paper from Oct 8. Check the abstract for which detector it uses and how the memory scales over long runs.

## Today's deep read

**TensorRT 11.4.0 release notes** — [link](https://docs.nvidia.com/deeplearning/tensorrt/11.4.0/getting-started/release-notes-11/11.4.0.html).

- **What to read:** the "Announcements" and "Breaking changes" sections first: dropped GPU architectures, CUDA versions and Python versions, and deprecated APIs. Then the list of fixed issues, filtered for operators your models use (attention, deformable conv, NMS and TopK, resize, LayerNorm). Then any notes on INT8, FP8 or FP4 quantization and on the ONNX parser.
- **How it could apply to you:** a TensorRT minor bump changes kernels and tactic choices, so latency and even accuracy can shift for the same ONNX file. Before upgrading a production detector or segmenter, rebuild the engine with 11.4 next to your current one. Then compare outputs on a fixed validation set (mAP or mIoU plus maximum per-box drift) and latency at your real batch size. If you also run ONNX Runtime with the TensorRT execution provider, check that ORT 1.31 supports TensorRT 11.4 before upgrading both together.
