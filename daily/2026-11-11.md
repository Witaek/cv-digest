## TL;DR
- **Ultralytics now ships pretrained text detectors, `yolo26{n,s,m,l,x}-text.pt`, and the OCR solution no longer needs PaddlePaddle.** Recognition now runs PP-OCRv6 (medium) as an ONNX model on ONNX Runtime. The checkpoints' own validation metrics go from 0.599 mAP50-95 (n) to 0.726 (x). OCR now also reads pages at any rotation.
- **INT8 exports keep the fragile parts in float.** On every GPU, RT-DETR's transformer now stays out of TensorRT INT8: the code says TensorRT 11.3/11.4 builds it broken, costing rtdetr-l 4.9–5.4 mAP. LiteRT static INT8 keeps YOLO's head output convs and decode in FP32. OpenVINO INT8 for the Intel NPU switches CNN heads to symmetric activations, which the code comment says is "about 2x faster".
- **Intel device names changed (8.4.210).** Use `device=npu` and `device=xpu` (Intel GPU) with `format=openvino` or `litert`. `intel:npu` / `intel:gpu` still work but log a deprecation warning. `Model.predict` is now thread-safe when one model is shared across threads with different args.

## Models & releases

- **Ultralytics 8.4.210: YOLO26 text detectors + rewritten OCR** — [PyPI](https://pypi.org/project/ultralytics/8.4.210/), [weights (n)](https://github.com/ultralytics/assets/releases/download/v8.4.0/yolo26n-text.pt), [recognizer](https://github.com/ultralytics/assets/releases/download/v8.4.0/PP-OCRv6_medium_rec.onnx). Uploaded Nov 10, 23:14 UTC. The assets were uploaded the same morning.
  - **Weights:** five sizes, 5.7 MB (n) to 126 MB (x), with a single `text` class. Each was trained for 50 epochs at 640 on a scene-text dataset. Validation metrics stored in the checkpoints (their own val split, box metrics):

    | model | P | R | mAP50 | mAP50-95 |
    |---|---|---|---|---|
    | yolo26n-text | 0.841 | 0.729 | 0.801 | 0.599 |
    | yolo26s-text | 0.869 | 0.773 | 0.844 | 0.660 |
    | yolo26x-text | 0.892 | 0.824 | 0.888 | 0.726 |

    (We didn't download m and l.)
  - **Recognition without Paddle:** a new `TextRecognizer` runs `PP-OCRv6_medium_rec.onnx` (77 MB) on ONNX Runtime ≥1.26 (Python 3.11+). It uses CUDA when available, with cuDNN `HEURISTIC` algo search so that each new line width doesn't trigger a re-benchmark. Crops are resized to 48 px high and batched in groups of 8 sorted by width. The code notes that batches of 32 "merged words on a dense page". The old `paddleocr`/PaddlePaddle dependency is gone from this path.
  - **Any page rotation:** the page's dominant text angle is estimated from the elongated word boxes, and the page is rotated upright. Both 0° and 180° are tried on the 8 widest words, and the more confident reading wins. Words are then grouped into lines, with a new line started at gaps over 1.5 text heights. Each word now has a `line` index. New defaults: `model=yolo26x-text.pt`, `imgsz=1280` (smaller images are never upscaled) and `max_det=1000`.
- **Ultralytics 8.4.209** — [PyPI](https://pypi.org/project/ultralytics/8.4.209/). Uploaded Nov 10, 18:55 UTC.
  - **Thread-safe predict:** each call's args and `save_dir` are now applied under the predictor's lock. Before, concurrent `model.predict(...)` calls with different `conf`/`classes` could pick up each other's settings.
  - **Validation with `classes=`** now filters during NMS. End-to-end heads keep ≥300 candidates before `max_det`, so filtered mAP no longer comes out low.
  - **`YOLO("rtdetr-*.yaml")`** now builds an RT-DETR model rather than a YOLO one.

## Edge & deployment

- **TensorRT INT8 for RT-DETR (8.4.210):** Model Optimizer's INT8 pass now excludes the AIFI encoder layer and the `RTDETRDecoder`, attention included, on every GPU. The code comment says TensorRT 11.3 and 11.4 build that block "broken in INT8 (rtdetr-l 4.9-5.4 mAP)", and that keeping it in float "adds ~1-2 mAP on 11.2". Before, only SM 12.1 (GB10, N1X) got this. The HGBlock squeeze-conv exclusion is still SM 12.1 only.
- **LiteRT static INT8 (`quantize=8`) for Detect models (8.4.210)** now marks the head output convs, coordinate normalization and the serving outputs as `NO_QUANTIZE`. The comment explains why: "int8 clips class logits and one output scale coarsens boxes". Expect slightly larger, slower but more accurate `.tflite` files. Re-export and re-check latency on your target.
- **OpenVINO INT8 for the Intel NPU (8.4.209/210):** when you export with `device=npu`, CNN detection models are calibrated with NNCF's `PERFORMANCE` preset (symmetric activations) rather than `MIXED`. RT-DETR is excluded. The code comment: NPU runs CNN detection heads "about 2x faster with symmetric activations; CPU and GPU gain little". Export now always traces on CPU for OpenVINO.
- **ONNX Runtime backend (8.4.209):** the CPU intra-op thread pool is capped at 8 threads (or the affinity count, if lower) unless `ORT_INTRA_OP_NUM_THREADS` is set. On big hosts running several workers, this cuts contention. On a dedicated 16+ core box, set the env var if you want all cores. On macOS (ORT ≥1.20), the CoreML EP now uses ML Program format. The comment says the old NeuralNetwork format "drifts from CPU and fails on semantic". Jetson's `onnxruntime-gpu` (without the `[cuda]` extra) is now accepted, not reinstalled.
- **Minor:** NCNN export no longer accepts `batch`. Triton client installs only `[http,grpc]`.

## Today's deep read

**Where INT8 breaks detectors: three exclusions in Ultralytics 8.4.209–8.4.210** — [8.4.210 sdist on PyPI](https://pypi.org/project/ultralytics/8.4.210/#files) (`utils/export/engine.py`, `utils/export/litert.py`, `utils/export/openvino.py`).

- **What to read:** in `engine.py`, the regex that collects `/model.N/(ma|decoder)/` nodes into `nodes_to_exclude` and the comment above it giving the TRT 11.3/11.4 numbers. In `litert.py`, the `update_quantization_recipe` call and the regex that keeps `Proto` and plain convs quantized but leaves the head outputs in float. In `openvino.py`, the preset switch that depends on `transformer`, `int8_detect` and the `npu` device.
- **Why it matters:** these are three separate runtimes, and each has a clear failure point under full INT8. On TensorRT, transformer attention in RT-DETR breaks. On LiteRT, the head's class logits get clipped and a single output scale coarsens the boxes. On the NPU, asymmetric activations double the head's cost. Last week RF-DETR 1.12.0 reported the same pattern with matmul-only INT8 on ONNX/OpenVINO (covered Nov 7). Mixed precision around the attention block and the head is becoming the norm for detector INT8.
- **How it could apply to you:**
  - If you built an RT-DETR INT8 engine on TensorRT 11.3/11.4, re-validate it now. A 5-mAP loss from a broken build is easy to miss when the speed numbers look good.
  - If you hand-roll INT8 for any detector, try the same exclusions first: the head output convs, the box decode and the attention blocks. Then measure mAP and latency against full INT8 on your own val set.
  - For Intel NPU targets, compare `PERFORMANCE` and `MIXED` presets on your model. The 2x figure comes from a code comment, not a published benchmark.
