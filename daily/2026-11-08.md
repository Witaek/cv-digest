## TL;DR
- **Ultralytics 8.4.205 adds an `OCR` solution and a scene-text OBB dataset.** A YOLO detector finds the text and PaddleOCR reads it, then the results are put in reading order. The new `scene-text-obb.yaml` merges COCO-Text and HierText legible words into a one-class OBB dataset (about 52k training images). No pretrained `scene-text-obb.pt` is published yet.
- **The new tiling from 8.4.204 already got a fix.** Merging now drops boxes cut off at a tile edge when a neighbouring tile saw the whole object. If you tried `tile=` on Friday, update before you compare mAP against SAHI.
- **The Paddle export is tested again, and `paddlepaddle-gpu` installs are now respected.** 8.4.207 puts all PaddlePaddle checks behind one `check_paddle()`, which won't replace an installed GPU build with the CPU one. It still excludes 3.3+, whose oneDNN CPU inference is broken.

## Models & releases

- **Ultralytics 8.4.205** — [PyPI](https://pypi.org/project/ultralytics/8.4.205/), [docs (scene text)](https://docs.ultralytics.com/datasets/obb/scene-text). Uploaded Nov 7, 16:43 UTC.
  - **New `solutions.OCR`** (`yolo solutions ocr`), described as "detect, recognize, and order scene text with a YOLO detector and a recognition backend":
    - **Inputs:** it takes box, OBB or segmentation models. For masks, it crops the minimum-area rectangle around the polygon. Crops that are at least 1.5× taller than wide are rotated 90° before they are read, so steep text still reads.
    - **Recognition:** `recognizer="paddleocr"` (the default) uses PaddleOCR's `TextRecognition` in batches of 16. Any callable that takes a BGR crop and returns `(text, confidence)` also works, so you can plug in your own recognizer.
    - **Reading order:** detections whose centres sit within half a line height of each other are grouped into a line. Lines are then sorted top to bottom, and words in each line left to right. Each result carries the text, recognition and detection confidence, and the polygon.
  - **`scene-text-obb.yaml`:** one class (`text`), built from COCO-Text and HierText legible words, converted to OBB polygons.
    - **Sizes:** train 43,686 + 8,281 images (65,919 + 862,577 words); val 4,927 + 1,724; test 5,073 + 1,634.
    - **Download:** about 24 GB, and it needs COCO 2017 images.
    - **Example training command from the file:** `yolo obb train data=scene-text-obb.yaml model=yolo26n-obb.pt imgsz=640`.
    - **Licences:** COCO-Text annotations are CC BY 4.0, HierText is CC BY-SA 4.0, and the image terms of COCO and Open Images also apply.
  - **Also:** `ObjectCropper` now runs per-image prediction instead of tracking. LiteRT and NXP exports now always run on CPU. DeepX export now requires `dx_com>=2.5.0`. Passing a boolean to `fraction=` now raises an error.
- **Ultralytics 8.4.206** — [PyPI](https://pypi.org/project/ultralytics/8.4.206/). Uploaded Nov 7, 19:27 UTC.
  - **OCR now uses PP-OCRv6** (`paddleocr>=3.7`, `paddlepaddle>=3.1`).
  - **Upside-down text:** a box can't tell 0° from 180°, so crops that PaddleOCR's orientation classifier marks as upside down are read a second time rotated 180°. The more confident reading wins. That costs one extra classifier pass per batch, plus a second recognition pass on the flipped crops.
  - **Polygon labels** are now drawn at the top-left of the enclosing box, for every OBB plot, not only OCR.
- **Ultralytics 8.4.207** — [PyPI](https://pypi.org/project/ultralytics/8.4.207/). Uploaded Nov 7, 21:31 UTC.
  - **Paddle export:** the export test is back on, and it now runs inference on the exported model too. The export also gets its own environment spec: Python 3.13, because PaddlePaddle wheels stop at cp313.
  - **New `check_paddle()`:** PaddlePaddle 3.x GPU builds are only on Paddle's own package index, so an installed `paddlepaddle-gpu` is now only version-checked, never reinstalled over. The CPU range stays at `>=3.0.0,<3.3.0`, or exactly `3.0.0` on ARM64, because of [Paddle #77340](https://github.com/PaddlePaddle/Paddle/issues/77340).
  - **IMX export:** Debian versions newer than Trixie now take the same install path as Ubuntu.
- **Release check (PyPI):** unchanged for RF-DETR 1.12.0, torch 2.15.0, torchvision 0.29.2, timm 1.0.31, supervision 0.31.5, transformers 5.22.2, Roboflow Inference 1.8.4, SAHI 0.14.0, ONNX Runtime 1.31.1, TensorRT 11.4.0.106, OpenVINO 2026.4.1, LiteRT 2.3.0, ExecuTorch 1.6.0, Triton 3.9.0, torchao 0.18.0, flash-attn 2.8.3.post2, Kornia 0.9.0, Model Optimizer 0.48.0, cuDNN 9.28.1.4 and DALI 2.4.0. YOLO27 weights are still not out.

## Edge & deployment

- **Tiled inference now handles objects cut at tile edges (8.4.205).** Friday's `ops.merge_tiles` (8.4.204) merged tiles with class-aware NMS. A large object cut by a tile edge could leave a partial box that survived NMS next to the full one. Now:
  - **Fragments are dropped.** A box touching an inner tile edge (within 2 px) counts as a fragment when another tile sees it clear of its edges. Fragments are left out before NMS.
  - **Some fragments come back.** A fragment returns if no kept box covers more than half of it, so an object that only ever appears cut isn't lost.
  - **Masks:** they can now come at a whole-pixel stride of the tile size, and tiled validation samples them at the target mask resolution. Tile masks waiting to be merged are 16× smaller, which cuts memory on large images.
  - **Training:** each source image's labels are counted once when computing class weights, not once per tile. Polygons cut by a tile are now clipped to their box instead of going through the polygon-clipping helper, which was removed.
  - **Takeaway:** mAP from a tiled run on 8.4.204 isn't comparable to one on 8.4.205+, so re-run it.

## Today's deep read

**Ultralytics `solutions/ocr.py` plus `scene-text-obb.yaml`** — [8.4.207 sdist on PyPI](https://pypi.org/project/ultralytics/8.4.207/#files), [scene-text dataset docs](https://docs.ultralytics.com/datasets/obb/scene-text).

- **What to read:**
  - `OCR.process` and `reading_order`. The file is about 120 lines and shows the whole detect → crop → recognise → order pipeline.
  - The dataset's `download:` block, which converts COCO-Text and HierText polygons to YOLO OBB labels.
- **Why it matters:** scene text (signs, labels, containers, plates, packaging) has usually needed a separate text-detection stack such as DBNet or PP-OCR's detector. This lets the YOLO model you already deploy do the detecting, so text gets the same export targets (TensorRT, ONNX, NPUs) as your other models. Only the recognizer stays in Paddle, or in whatever callable you plug in.
- **How it could apply to you:**
  - **Train your own detector.** With no pretrained checkpoint out yet, train `yolo26n-obb` on the dataset and evaluate on your own footage. HierText has about 100 words per image, so check `max_det` and NMS settings on dense text.
  - **Keep recognition apart from detection.** For deployment, pass a callable that wraps your own recognizer (a TensorRT or ONNX CRNN or PARSeq, say). That avoids running PaddlePaddle in production and the `<3.3.0` CPU pin.
  - **For high-resolution cameras,** combine it with `tile=` from 8.4.204/205. Small text is where tiling helps most, and the fragment handling above keeps long lines that cross tile edges from turning into duplicate boxes.
