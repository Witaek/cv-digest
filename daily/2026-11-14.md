## TL;DR
- **transformers 5.23.0 turns its exporters into a load-and-run API.** `ExportedModel.save_pretrained()` / `from_pretrained()` now round-trip ONNX, OpenVINO, ExecuTorch and Dynamo exports with recorded metadata. A new `OnnxConfig(ort_fusions="cpu"|"cuda"|"webgpu"|"dml")` fuses the graph into ONNX Runtime's own ops. **Breaking:** OpenVINO `compress_to_fp16` now defaults to `False`, and `output_path` is gone from the export configs.
- **Ultralytics 8.4.212 fixes the ONNX Runtime CUDA install on CUDA 12 machines.** PyPI `onnxruntime-gpu` 1.27+ only ships CUDA 13 builds, so on a CUDA 12 PyTorch, Ultralytics now pins `onnxruntime-gpu[cuda]<1.27`. CPU ONNX inference now sizes its threads by physical cores and respects Docker `--cpus` limits.
- **Seg and pose validation now report per-class mAP50, mAP75 and mAP50-95 (8.4.212).** Before, the per-class summary had only P, R and F1 for masks and keypoints. Semantic segmentation summaries add per-class pixel accuracy.

## Edge & deployment

- **transformers exporters, 5.23.0:**
  - **`ExportedModel`:** an export now returns an object you call like the source model. It records the export dtype, traced input shapes, and the output pytree, so outputs come back as the usual `ModelOutput`. `save_pretrained()` writes the program plus metadata and config; `ExportedModel.from_pretrained(dir, device="cuda")` loads it through a per-backend runner (ONNX Runtime, OpenVINO, ExecuTorch, Dynamo).
  - **ORT fusions:** `OnnxConfig(optimize=True, ort_fusions="cuda")` runs onnxscript's `optimize_for_ort` (norms, attention, GELU) plus extra rewrites for rotary embeddings, `GroupQueryAttention`, MoE and packed projections. The fused graph only runs on ONNX Runtime; the CUDA variant needs onnxruntime ≥1.28.0. Most of this targets transformer encoders and decoders, so ViT/DINO backbones and DETR-style encoders are the likely CV beneficiaries.
  - **Breaking defaults:** `OpenVINOConfig.compress_to_fp16` flipped from `True` to `False` ("off by default for the narrower range"), so OpenVINO IRs from transformers are now FP32 on disk (2× bigger) unless you opt in. `output_path`, `external_data`, `export_params` and `keep_initializers_as_inputs` were removed from the ONNX config; saving goes through `ExportedModel.save_pretrained()`.
- **ONNX Runtime on CPU (Ultralytics 8.4.212):** `intra_op_num_threads` is now `min(8, physical cores, affinity mask, cgroup v2 cpu.max quota)`, at least 1. Before, it counted logical CPUs and ignored container quotas, so a `--cpus=2` container on a 64-thread host ran 8 threads and lost time to throttling. Re-benchmark containerized CPU latency.
- **TensorRT install check (8.4.212):** a plain `tensorrt` distribution (as in NVIDIA containers and JetPack) now satisfies the requirement, so Ultralytics no longer tries to pip-install `tensorrt-cu{N}` on top of it.

## Today's deep read

**The transformers 5.23.0 export round-trip** — [transformers 5.23.0 sdist on PyPI](https://pypi.org/project/transformers/5.23.0/#files) (`exporters/base.py`, `exporters/metadata.py`, `exporters/runners/`, `exporters/onnxruntime_fusions.py`).

- **What to read:**
  - In `base.py`, `ExportedModel`: `save_pretrained`, `from_pretrained` and `to(device, providers=..., session_options=...)`.
  - In `metadata.py`, what gets recorded per graph (dtype, traced shapes, input/output names, output tree spec and constants). This is what lets the runner rebuild `ModelOutput` objects.
  - In `onnxruntime_fusions.py`, `_STEPS` (around line 1396): the ordered rewrite pipeline and which steps apply per provider.
  - In `configs.py`, the new defaults (`compress_to_fp16=False`) and the `ort_fusions` validation.
- **Why it matters:** until now, exporting a transformers vision model (DINOv3, RT-DETR, D-FINE, RF-DETR, SAM) meant writing your own wrapper to map ORT outputs back to `logits`/`pred_boxes` before calling the image processor's `post_process_object_detection`. If the runner returns real `ModelOutput`s, the same post-processing code can drive both PyTorch and ONNX/OpenVINO, which makes accuracy parity tests much simpler.
- **How it could apply to you:**
  - Export one detector from transformers (e.g. RT-DETR or D-FINE) with and without `ort_fusions="cuda"`. Check the fused graph's node types in Netron, compare latency with ORT CUDA EP and TensorRT EP, and run the same `post_process_object_detection` on both outputs for a mAP diff.
  - If your pipeline exports OpenVINO IRs through transformers, set `compress_to_fp16=True` explicitly to keep your current artifact sizes.
  - Check whether the fused ops (e.g. `com.microsoft` attention/norm ops) fall back to CPU under the TensorRT EP before adopting fusions in a TensorRT pipeline.
