## Top papers

- **DriveOSS: Dataset and Benchmark for 3D Anomaly Segmentation and Open-set Semantic Segmentation in Autonomous Driving** — [link](https://arxiv.org/abs/2610.32612), [code + data](https://github.com/chrisyan/DriveOSS). From Zhiran Yan, …, Gordon Elger. Accepted to WACV 2027.
  - **What it is:** a 3D segmentation benchmark where some objects at test time belong to no training class. The authors call it the first real-world multimodal dataset of this kind. It has 12,661 synchronized, annotated frames from six surround-view RGB cameras, a 128-beam LiDAR and GPS/IMU, across 52 scenes in clear, night, cloudy, rain and snow conditions.
  - **Protocol:** training scenes contain only known classes. Validation and test scenes add unknown objects, labelled as an outlier class.
  - **Result:** the authors say unseen objects "remain a major challenge" for current 3D perception. The baseline numbers are in the paper; we read only the abstract.
  - **Why it matters:** STU (CVPR 2025), an earlier 3D anomaly benchmark, is LiDAR-only. DriveOSS pairs cameras and LiDAR, so camera-LiDAR fusion stacks can be scored on unknown objects.
- **Distortion-Aware Spatiotemporal Learning for Real-Time Wide-Angle Video Rectification (FastVC)** — [link](https://arxiv.org/abs/2610.32500). From Lang Nie, …, Bin Xiao.
  - **What it does:** corrects the stretching of people's bodies near the edges of wide-angle video. Earlier methods mostly corrected faces only, ran slowly and jittered between frames.
  - **How it works:** FastVC has three parts:
    - a distortion-aware thin-plate spline that places more control points toward the edges of the frame, at no extra compute;
    - local attention that reuses features from previous frames;
    - alignment losses applied only on anchor frames, so per-frame accuracy and frame-to-frame stability are trained separately.
  - **Numbers:** the abstract claims state-of-the-art fidelity and stability at 57.0 FPS. It doesn't name the hardware or give a parameter count. The authors also release the first benchmark for full-body wide-angle video correction. No code is linked.
  - **Why it matters:** rectifying the image before detection or pose estimation helps on video-conferencing, dashcam and retail fisheye cameras. Check what GPU the 57 FPS was measured on before planning around it.
- **Consommé: Conditioned Token Merging for Split Inference** — [link](https://arxiv.org/abs/2610.32794), [code](https://github.com/Borakleon/Consomme). Listed yesterday as unread; the code is new information. The repo trains a gate that merges ViT tokens at a split block, so fewer tokens go from the device to the server. It ships ImageNet classification recipes for ViT-B/16, DeiT-S and DeiT-Ti (e.g. `--split_block_nr 3 --gate_top_k 8`). The README gives no accuracy or bandwidth numbers, and the abstract page was rate-limited.
- **Video-MemComp: Taylor-Guided Sensitivity-Aware Memory Management for Streaming Video Understanding** — [link](https://arxiv.org/abs/2610.32784), [code](https://github.com/hhnk666/videomemorycompress). Also listed yesterday as unread; the repo is new information.
  - **What it does:** compresses the KV cache of video LLMs for streaming input so memory stays constant (O(1)) however long the video runs, with no offloading or retrieval.
  - **How it works:** it merges keys before rotary position encoding is applied, prunes KV entries within each layer, and splits the memory budget across layers by how sensitive each layer is.
  - **Code and results:** code is released for Qwen2-VL-7B, Qwen2.5-VL-3B/7B, LLaVA-OneVision-7B and InternVL-3.5-2B, evaluated on VideoMME, MLVU, EgoSchema and OVO-Bench. The README says it beats the full KV cache on MLVU at 6K/12K/24K budgets, but the numbers are only in figures. It was accepted at ACM MM '26.

## Models & releases

- **Ultralytics 8.4.190** — [release](https://github.com/ultralytics/ultralytics/releases/tag/v8.4.190). Released Oct 26.
  - **Training:**
    - **Mask-IoU-aware assignment for YOLO26-seg (#26773):** positive matches now count mask overlap as well as box overlap. Mask decoding during assignment is capped and runs at higher precision, to limit memory and avoid overflow. Ultralytics says other segmentation models and inference/export behavior are unchanged, and gives no mAP numbers.
    - **AutoBatch (#26894):** memory accounting is fixed, so batch size now follows the GPU memory that is actually free.
    - **Unlabelled NDJSON classification images (#26865):** these are now skipped instead of being silently labelled class 0.
  - **Exports:**
    - **RKNN:** INT8 export now works for depth models, with mixed precision on the layers prone to error (#26885).
    - **CoreML:** segmentation NMS exports no longer produce duplicate detections (#26862).
    - **OBB:** FP16 embedded-NMS precision is fixed (#26823).
    - **CoreML on MPS:** float64 outputs no longer crash inference (#26896), and CoreML inference no longer downgrades NumPy (#26863).
  - **Inference:** OpenVINO CPU inference now prefetches images (#26897), and RLE encoding in segmentation `save_json` is vectorized (#26898).
- **transformers 5.21.0** — [release](https://github.com/huggingface/transformers/releases/tag/v5.21.0) (notes read via the [releases.sh mirror](https://releases.sh/hugging-face/transformers-releases.md)). Released Oct 26.
  - **New vision models:**
    - **MiniCPM-OCR (#49920):** a SigLIP encoder paired with Qwen3.5, for scanned pages, receipts and tables.
    - **UltraVBert (#49685):** visual document retrieval that tiles each page into 512-pixel crops plus a global view, up to 27 tiles by default.
  - **Perception fixes:**
    - **SAM:** multi-zoom crops in the mask-generation pipeline are fixed (#49689).
    - **Detection models:** several had loading issues tied to module tying, now fixed (#49827). DETR conversion scripts now load through `from_pretrained` (#49830).
    - **Transparent PNGs:** image processors now composite them onto white instead of black (#49079). This changes the inputs if your data contains transparent PNGs.
- **Release check (PyPI):** besides the three releases above, unchanged since yesterday: torch 2.14.1, torchvision 0.29.1, timm 1.0.30, supervision 0.31.2, rfdetr 1.11.2, Roboflow Inference 1.8.3, TensorRT 11.4.0.106, OpenVINO 2026.4.1, LiteRT 2.3.0, ExecuTorch 1.5.1, Triton 3.8.0, Model Optimizer 0.47.0, torchao 0.18.0 and flash-attn 2.8.3.post2.

## Today's deep read

**DriveOSS** — [paper](https://arxiv.org/abs/2610.32612), [code + data](https://github.com/chrisyan/DriveOSS).

- **What to read:**
  - **How outliers are labelled:** which unknown objects appear in the test scenes, and how they are labelled in LiDAR versus the camera views.
  - **Metrics:** anomaly segmentation is usually scored with AUPR and FPR95, and open-set segmentation with mIoU over known classes plus outlier recall. Check which ones the paper uses.
  - **Baselines:** which baselines fail worst at night and in snow, and whether camera-LiDAR fusion beats LiDAR alone on outliers.
- **How it could apply to you:**
  - **Score your current model:** if you run a 3D semantic segmentation model, evaluate it on the out-of-distribution split as it is. Then add a simple anomaly score, such as max-logit or energy on each point, and see how much outlier recall you get without retraining.
  - **Check the calibration:** the scene split (known classes in training, unknowns only at test) is a clean setup for tuning the threshold at which a point is flagged as unknown, before deploying that threshold in an AV or robot stack.
