## Top papers

- **SpaceCache: Intermediate Feature Reuse for Efficient Semantic Segmentation on Point Cloud Streams** — [link](https://arxiv.org/abs/2610.21207). From Yang, Kang and Kim. Consecutive LiDAR sweeps overlap heavily, yet stream segmenters recompute every point each frame. SpaceCache keeps intermediate transformer features for regions already seen in earlier frames and reuses them, training-free. It reports up to 1.65× speedup with less than 1 mIoU drop on nuScenes, Waymo and ScanNet. The listing gives no per-backbone latency or hardware, and no code link.
- **TEAL: Pixels to Tokens: Token Space Efficient Active Learning for Low-Budget Semantic Segmentation** — [link](https://arxiv.org/abs/2610.20881). By Cicek, Wong, Rambhatla et al. It is pixel-level active learning on a frozen DINOv3 ViT: pixels to label are chosen by diversity in token space, then refined by uncertainty. With one labeled pixel per image it beats the strongest baseline by up to +24.36 mIoU. With 10 pixels per image it reaches up to 97% of fully supervised performance. This is a strong argument for "frozen DINOv3 plus a few clicks" as a labeling strategy for new segmentation domains.
- **Decision-FLIP: Budget-Free Structured Pruning for Gaussian Occupancy Models** — [link](https://arxiv.org/abs/2610.20917). It scores each Gaussian by how many voxel occupancy decisions flip when it is removed, prunes without a preset budget, and compiles a physically smaller checkpoint. Results: 12–79% of eligible rows removed and 7–45% lower bank/query latency, but whole-model savings are only up to 8.0% latency and 16.6% peak memory. Semantic mIoU moves by at most 0.18. The gap between component and end-to-end savings is the honest number to plan with.

## Models & releases

- **supervision 0.31.0** — [changelog](https://supervision.roboflow.com/latest/changelog/), [PyPI](https://pypi.org/project/supervision/0.31.0/). Released Oct 16.
  - **New:** `sv.DepthMap`, `sv.DepthAnnotator` and `sv.DepthCamera`, which convert disparity to meters and store the median depth per box in `detections.data["depth_m"]`. Depth maps load from Ultralytics, Transformers, Roboflow Inference, PNG16 and PFM. Also new: `sv.metrics.KeyPointMeanAveragePrecision` (COCO keypoint eval), mask targets in `ConfusionMatrix`, and a `coord_transform` option so line/polygon zones work with a moving camera.
  - **Removed:** `sv.ByteTrack` (use `ByteTrackTracker` from the `trackers` package), `sv.LMM`/`Detections.from_lmm` (use `sv.VLM`/`from_vlm`), and the `supervision.keypoint` module (use `supervision.key_points`).
  - **Metric changes:** `MeanAverageRecall` now applies its detection limit per class per image, so mAR values change versus 0.30.x. Re-baseline any eval dashboards that use it.
- **transformers 5.20.1** — [release summary](https://releases.sh/hugging-face/transformers-releases), [PyPI](https://pypi.org/project/transformers/5.20.1/). Released Oct 16. It restores `from_pretrained` on torch 2.7 (and DTensor sharding on 2.6/2.7) and fixes HunYuan-VL batched image assignment. It also adds Reflection AI's Beam text model. No new vision architectures.
- **Ultralytics 8.4.179** — [PyPI](https://pypi.org/project/ultralytics/8.4.179/). Uploaded Oct 17 11:24 UTC, one day after 8.4.178. The changelog could not be read.

## Edge & deployment

- **DefoliationCAM** — [link](https://arxiv.org/abs/2610.20879). This is a solar-powered field camera that runs YOLOX-Nano localization plus a 1.08M-parameter MobileNet-based severity classifier (against 23.52M for ResNet-50) on a Jetson Orin Nano with TensorRT FP16. It takes about 1.5 s per 4K image and sends results over LoRa. Synthetic augmentation raised macro-F1 from 0.768 to 0.838. It is a small agricultural paper, but a realistic reference for a detect-then-classify pipeline on 4K images under a power budget.

## Today's deep read

**TEAL** — [link](https://arxiv.org/abs/2610.20881).

- **What to read:** how the pixels are chosen. Look at which DINOv3 layer the token-space diversity uses, how candidates are clustered, and what the uncertainty step adds on top. Then the budget curves (1, 5, 10 pixels per image) on each dataset against the strongest baseline, and how the segmentation head is trained from such sparse labels. Check which DINOv3 size was used, because the 97% figure may depend on a large frozen backbone.
- **How it could apply to you:** in a new segmentation domain, the usual cost is dense masks for thousands of images. If a frozen DINOv3 plus about 10 well-chosen clicks per image gets near full supervision, label the clicks, train the light head, use it to pseudo-label densely, and then distill into your real-time segmenter. The selection step also works as a tool that tells annotators which pixels to click, so it fits into existing labeling platforms.
