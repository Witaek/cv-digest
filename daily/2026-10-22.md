## TL;DR
- **TorchTPU is open source (Google + Meta).** It is a native PyTorch backend for TPUs that does not go through JAX: `model.to("tpu")` and `torch.compile(model, backend="tpu")`. DINOv2, SigLIP, CLIP, Swin, ConvNeXt, ViT, ResNet and DETR are validated out of the box, and 638 of 657 Hugging Face architectures (97%) match GPU numerics.
- **FocusOVD (Zhengzhou University) adds three small modules to a frozen-CLIP open-vocabulary detector to help with small objects.** It reaches 36.3 novel AP50 on COCO-OVD, +1.3 over CORA, and 33.7 AP on LVIS-OVD. There is no code yet.
- **WinARDet (Qibin Hou's group) fixes repeated boxes when an MLLM detector lists many objects.** On the RSDense benchmark, redundant predictions drop from 35.48% to 13.00% and recall rises from 36.82 to 45.23. Peak training memory falls by 25–34%. Code, weights and data are out.

## Top papers

- **FocusOVD: Geometric and Contextual Feature Refinement for Open-Vocabulary Small-Object Detection** — [link](https://arxiv.org/abs/2610.27479). From Kou, Bai, Chen, Li, Jiu (Zhengzhou University) and Jing (Sinosteel Zhengzhou), posted Oct 20.
  - **The idea:** the frozen VLM backbone is left untouched. Three light modules address the usual reasons small objects get missed:
    - **RCFF:** learned, normalized per-level weights in the FPN, to balance shallow detail against deep semantics.
    - **RPGConv:** a residual "pinwheel-shaped" gated convolution on C3 that strengthens local geometric responses.
    - **RCGLU:** a residual convolutional GLU on RoI features between RoIAlign and the box head.
  - **Numbers:** 36.3 novel AP50 on COCO-OVD, ahead of CORA (+1.3), UniDetector (+1.1) and SAMP (+1.5). For reference, the table lists RegionCLIP at 31.4 and CoDet at 30.2. LVIS-OVD overall AP is 33.7, +0.6 over the best competitor.
  - **Missing:** the part we could read did not include the small-object AP breakdown, the exact CLIP variant, or any FPS figure. No code is linked.
- **WinARDet: Compressed Window Auto-Regression for Long-Horizon Vision-Language Grounding** — [link](https://arxiv.org/abs/2610.19419), [code](https://github.com/facias914/WinARDet), [weights](https://huggingface.co/facias/WinARDet), [demo](https://huggingface.co/spaces/hugging-apps/winardet). From Wang, Kuang, Yin, Li, Zeng, Zhang, Guo, Li and Qibin Hou. It was posted mid-October and reached HF Daily Papers this week.
  - **The problem:** MLLM detectors write every box as text tokens. In dense scenes the output gets very long, and the model starts repeating coordinates.
  - **The fix:** WinAR splits the output into windows. Decoding is exactly autoregressive inside the current window, and finished windows are compressed into a fixed number of latent memory tokens. It also handles oriented (quadrilateral) boxes and parallel decoding.
  - **Numbers:**
    - **On RexOmni:** RSDense redundancy goes from 35.48% to 13.00% and recall from 36.82 to 45.23. Peak training memory goes from 57.62 to 42.97 GB.
    - **On Locate Anything:** peak training memory goes from 67.38 to 44.43 GB.
  - **Not reported:** model size, license and latency.
- **S-Agent 2.0: Spatial Reasoning with a General Coding Agent** — [link](https://arxiv.org/abs/2610.28354), [code](https://github.com/Ropedia/S-Agent-2.0). From Gong, Wang, … Fangzhou Hong, Zhaoxi Chen, Ziwei Liu. It had 98 upvotes on HF. An off-the-shelf coding agent (Codex or Claude Code) drives a command-line 3D perception toolkit. It keeps a persistent scene memory and describes each measurement in plain spatial language before the VLM answers.
  - **Open model (Qwen3.8-27B):** 66.5 on MMSI-Bench and 82.3 on ReVSI. The tools add +13.9 and +20.5, and SpatialClaw with the same backbone scores 62.6 and 74.5.
  - **Closed model (Gemini-3.8-Flash):** 74.1 and 90.5, against 67.0 and 79.7 without tools.
  - **Takeaway:** for metric spatial questions, calling real depth, detection and 3D tools still beats asking the VLM to judge geometry by eye.
- **Causal Spatiotemporal State Evolution for Monocular 4D Reconstruction** — [link](https://arxiv.org/abs/2610.27594). This is a feed-forward model that works causally (streaming), so it suits online use. A Mamba variant carries state from frame to frame and scans in complementary directions, and one motion field built from the predicted camera and depth supervises flow. It claims SOTA on video depth, camera pose and optical flow. We could read only a truncated abstract, with no numbers.
- **Long-wave Infrared Polarimetric Image Fusion for Vehicle Detection** — [link](https://arxiv.org/abs/2610.27022). A Mamba-based model fuses LWIR intensity with the degree of linear polarization (DoLP). On the new AIR-LWIR-Pol dataset (1,901 image pairs), YOLO11 on the fused images gets 55.0 mAP50 and 29.4 mAP50-95. This is relevant for night-time or thermal aerial detection. No code is linked.

## Edge & deployment

- **CodecMotion-OAD** — [link](https://arxiv.org/abs/2610.27015). It replaces optical flow with the motion vectors already in the compressed video stream for online action detection. On THUMOS'14 it gets 68.3 mAP, against 70.9 for RGB+flow, and runs 11.48x faster on CPU and 2.04x faster on GPU. For camera pipelines that already decode H.264/H.265, this removes the cost of computing flow. No code is linked.
- **EdgeKernelBench** — [link](https://arxiv.org/abs/2610.24648). A benchmark for LLM-written kernels on edge backends. Workloads go from single operators to small model graphs, all expressed in one shared IR, with TVM as the reference compiler. The best single-shot model compiles correct kernels 64.5% of the time, but only 25.5% of them beat the reference (Fast@1.0). The authors' layered agent, LEKA, which handles compute, scheduling and memory as separate steps, reaches 43.5% Fast@1.0 on the agent subset. Claude Code with the same base model gets 26.1%, and direct generation 13.0%. We could not read which devices were tested (arXiv 429); these figures come from a secondary write-up.
- **Rate as a Feature: FiLM conditioning for event-camera GNNs** — [link](https://arxiv.org/abs/2610.26933). Conditioning on the event rate adds about 0.2M parameters. It improves N-Caltech101 to 67.2% (+6.3 pp) and DVS128 Gesture to 82.5% (+14.0 pp). Code is promised on acceptance.

## GPU / CUDA / PyTorch

- **Introducing TorchTPU** — [blog](https://pytorch.org/blog/introducing-torchtpu/), [repo](https://github.com/google-pytorch/torch_tpu), [docs](http://torchtpu.readthedocs.io/). Posted Oct 20 (we missed it yesterday). Google and Meta built it, and the post says it already runs in production for some large Google Cloud customers.
  - **Usage:** `model.to("tpu")`, `torch.compile(..., backend="tpu")` (with `dynamic=False` forced for now), and `dist.init_process_group(backend="tpu_dist")` for distributed runs.
  - **Eager modes:** there are three. DeferAndFuse is said to be ≥50% faster than Strict and to use less peak HBM.
  - **Coverage:** about 450 ATen ops forward and backward. Custom kernels can come from Pallas, Tokamax or Helion (experimental). DTensor and FSDP are supported, and vLLM, SGLang and TorchTitan are integrated. 98% of 4,917 HF models run without crashing.
  - **Numbers:** FLUX.1-dev training steps drop from 11.49 s to 2.78 s after optimization. On TorchTitan, Qwen3 MoE 235B runs at 1,828 TPS on 64 TPU v7 chips, against 1,937 TPS for JAX/MaxText.
  - **Caveat:** the post says tensor shapes tuned for GPUs usually need re-tuning on TPU.
- **NVIDIA Technical Blog:** the five Oct 21 posts cover agent security, data-center digital twins, DSX POD and protein design. There is nothing on TensorRT, Jetson or vision.

## Today's deep read

**FocusOVD** — [paper](https://arxiv.org/abs/2610.27479).

- **What to read:**
  - **Ablation table:** how much each of RCFF, RPGConv and RCGLU adds on its own. The question is whether the gain is mostly fusion (cheap) or RoI refinement (it adds cost per box).
  - **Small-object breakdown:** the S/M/L AP split. A paper that targets small objects needs the gain to show up in AP_S, not only in overall novel AP50.
  - **Baselines:** the comparison is against CORA, UniDetector and SAMP, all two-stage or region-based. It is worth checking whether the modules would carry over to DETR-style open-vocabulary detectors (Grounding DINO, OmDet, YOLO-World).
  - **Parameter and latency cost:** we could not see it. If the paper does not report it, estimate it yourself before adopting.
- **How it could apply to you:** if you run an open-vocabulary detector with a frozen CLIP backbone on drone, retail-shelf or inspection imagery, these three modules sit outside the backbone. You can try them by fine-tuning only the neck and head on your own data.
  - **Cheapest first:** start with RCFF, which only reweights FPN levels and adds almost no latency.
  - **Measure it:** report AP_S on your own small-object slice, not only overall AP.
  - **Code:** until code appears, the paper descriptions are short enough to reimplement in an MMDetection or Detectron2 neck.
