## TL;DR
- **Tencent's WeVisOne-VL (2B/4B, weights out) is the strongest open "VLM as detector" so far.** The 4B reaches 57.1 F1 on COCO detection (GroundingDINO-T: 56.6), 81.8 on RefCOCOg and 84.5 cIoU on RefCOCO testA. A 9.6M-parameter pixel decoder outputs masks and alpha mattes without SAM.

## Top papers

- **WeVisOne-VL: Unified Visual Perception from Objects to Pixels** — [link](https://arxiv.org/abs/2610.31329), [code](https://github.com/Tencent/WeVisOne-VL), [weights](https://huggingface.co/collections/tencent/wevisone-vl). From Tencent's WeChat Vision team (Tianming Liang, …, Jing Lyu). It is the top HF daily paper (≈220 upvotes).
  - **The idea:** one VLM covers detection, referring, counting, pointing, OCR, segmentation and matting, all as structured next-token prediction. A special `<OBJ>` token feeds a 9.6M-parameter pixel decoder that reads multi-level Qwen3-VL ViT features and outputs instance masks or alpha mattes, with no SAM in the loop. Training is a three-stage SFT curriculum followed by mixed-task RL, and it explicitly learns to return `None` for absent objects.
  - **Numbers (2B / 4B; detection F1 is averaged over IoU 0.5–0.95):**
    - **Detection:** COCO 55.2 / 57.1, LVIS 53.3 / 55.3, VisDrone 40.4 / 44.7. GroundingDINO-T gets 56.6 / 38.8 / 38.5 on the same three.
    - **Referring:** RefCOCOg 78.2 / 81.8, with rejection of absent targets at 50.2% / 67.4% (Rex-Omni-3B: 0.5%).
    - **Referring segmentation:** RefCOCO testA 82.9 / 84.5 cIoU, ReasonSeg val 60.9 / 71.2 gIoU.
    - **Matting:** P3M-500-NP MAD 6.6 / 7.3 ×10⁻³, against 15.4 for SAM2-Matting.
    - **OCR:** ICDAR2015 F1 42.6 / 47.8, against 25.6 for PP-OCRv5.
  - **Why it matters:** a 2B model that matches or beats GroundingDINO-T on COCO, rejects absent queries, and gives masks without a second model is a realistic single-model labeler or open-vocabulary front end.
  - **Caveats:** the repo gives no latency or VRAM figures and no weight license (the code is Apache-2.0). Inference was capped at 1,960 visual tokens per image with greedy decoding.
- **F2G-Pose: Geometry-Aware Foundation Feature Lifting for Direct RGB-D Category-Level Object Pose Estimation** — [link](https://huggingface.co/papers/2610.31623), [code](https://github.com/jrryzh/F2G-Pose), [weights](https://huggingface.co/J3rr1/F2G-Pose). From Fudan/SII (Jinyu Zhang, …, Yanwei Fu); accepted at NeurIPS 2026 per the authors.
  - **How it works:** from one segmented RGB-D view, it lifts frozen RADIO features onto the partial point cloud, tokenizes local geometry with DGCNN, and runs a Mixture-of-Experts transformer. It jointly predicts 6D pose, metric size and the completed shape in the camera frame. The task network is trained only on synthetic SOPE data.
  - **Numbers:** claims SOTA on SOPE and ROPE (the abstract gives no values), 28 FPS for pose-only inference (hardware not given), and transfer to HouseCat6D and real HANDAL objects.
  - **Why it matters:** a single-pass, real-time alternative to render-and-compare pipelines for grasping or bin picking, trained without real labels.
- **Foundation4D: Towards a unified perception and reconstruction model for autonomous vehicles** — [link](https://arxiv.org/abs/2610.30340). From NVIDIA (26 authors, including Laura Leal-Taixé and Aljoša Ošep); posted Oct 21.
  - **The model:** one feed-forward model on multi-camera driving video does depth/geometry, 3D detection, semantic occupancy and Gaussian reconstruction. It uses a shared backbone with factorized spatiotemporal attention, plus pose-graph optimization and cross-window track linking for long videos.
  - **Numbers:** with per-benchmark fine-tuning it reports the best depth AbsRel on Waymo and nuScenes, the best detection mAP on nuScenes and the best occupancy mIoU on OpenOccupancy among compared methods (the abstract gives no absolute values). Co-training with geometry and occupancy adds +1.2 mAP on top classes, and co-training with detection cuts camera-to-rig translation error by 13.4%.
  - It also releases the PAI-Foundation4D benchmark (1,253 clips with dense depth and occupancy). No code is linked.
- **RLSplat: Resource-Linear Budget Control for Feed-forward 3D Gaussian Splatting** — [link](https://arxiv.org/abs/2610.27712), [code](https://github.com/mlvlab/RLSplat). Existing budget-controlled feed-forward 3DGS predicts a dense set and then prunes it, so cost barely moves with the budget. RLSplat allocates the Gaussian budget per region with a learned policy and decodes each Gaussian with local neighbor attention only. It beats the strongest baseline with 4x fewer Gaussians and is up to 4.1x faster with 9.6x less peak memory at low budgets (zero-shot; the abstract gives no PSNR).

## Edge & deployment

- **TensorRT Global Performance Tuner (TensorRT 11.1+)** — [part 1](https://developer.nvidia.com/blog/scaling-nvidia-tensorrt-performance-optimization-beyond-a-single-build-route-with-the-global-performance-tuner-part-1/), [part 2](https://developer.nvidia.com/blog/scaling-nvidia-tensorrt-performance-optimization-beyond-a-single-build-route-with-the-global-performance-tuner-part-2/), [docs](https://docs.nvidia.com/deeplearning/tensorrt/latest/performance/tuning.html). Posted Oct 23.
  - **What it does:** instead of one fixed heuristic build, `trtexec` expands a "build route" expression over more than 200 knobs (graph transforms, fusions, precision, memory placement, Q/DQ handling). It builds each candidate, drops those that crash or fail your accuracy metric against golden data, and keeps the fastest.
  - **Search modes:** `fast` changes one knob at a time, `mixed` then combines the winners, and `full` tries the full Cartesian product.
  - **Useful flags:** `--dryRun`, `--tuningCacheFile` with `--continue` to resume a sweep, and `--saveAllEngines`. C++ users get `IBuilderConfig::setBuildRoute`. A Python path comes with Torch-TensorRT 2.15.
  - **Numbers:** 1.14x–1.63x over the default route on ten workloads. The posts name no models or GPUs and give no tuning-time cost, and there is no vision example.
  - Relevant if an INT8 or FP8 detector loses accuracy only on some fused layers: the accuracy gate lets the tuner keep the fast kernels elsewhere.

## Today's deep read

**WeVisOne-VL** — [paper](https://arxiv.org/abs/2610.31329), [code](https://github.com/Tencent/WeVisOne-VL), [demo](https://huggingface.co/spaces/liangtm/WeVisOne-VL).

- **What to read:**
  - **Metric:** detection is scored as F1 over IoU 0.5–0.95, not COCO AP. A VLM emits one set of boxes with no score ranking, so 57.1 F1 is not comparable to a detector's 57 AP. Find out whether the report also gives AP, and how GroundingDINO-T's threshold was chosen for the F1 comparison.
  - **Pixel decoder:** how the `<OBJ>` hidden state conditions the 9.6M decoder on multi-level ViT features, and how masks compare to SAM-family masks on boundary quality.
  - **Rejection training:** the 67.4% RefCOCOg and 96.4% WeRef rejection rates come from data and RL design. This is the part most worth copying if you have ever had a grounding model hallucinate boxes for absent classes.
  - **Cost:** tokens per image (capped at 1,960) and decode length for dense scenes. Dense200 at 71.3 F1 implies long outputs, so estimate latency yourself, since none is reported.
- **How it could apply to you:**
  - **Auto-labeler first:** use the 4B as a box-plus-mask auto-labeler for a new class set, then distil into your real-time detector (YOLO26 or RF-DETR).
  - **Measure on your data:** run it on a held-out split with vLLM, record per-image latency on your GPU, and compare label quality against GroundingDINO plus SAM 2 before switching pipelines.
  - **License:** check the weight license on the HF model cards before any commercial use.
