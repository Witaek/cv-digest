## TL;DR
- **Ultralytics 8.4.213 decodes segmentation masks inside each box, not over the full frame.** A new `ops.process_mask_local` keeps time and memory proportional to the summed box areas instead of N × H × W. `Results.masks` now stays box-local until you read `.data`. This mostly speeds up crowded scenes and `retina_masks=True`.
- **Two label-correctness fixes in 8.4.213:** `yolo_bbox2segment` (box labels → SAM masks) now keeps class IDs aligned with the masks SAM actually returned. Tiled inference no longer lets a box of one class suppress a fragment of another class.
- **AlbumentationsX 2.6.3 removes `ModeFilter`**, added in an earlier 2.6.x release. Pipelines that use it will break on upgrade. `ThinPlateSpline` now caches its grid basis per image size, and `SaltAndPepper` uses a sparse path at low noise amounts.

## Models & releases

- **Ultralytics 8.4.213** — [PyPI](https://pypi.org/project/ultralytics/8.4.213/). Uploaded Nov 14, 18:48 UTC.
  - **Box-local mask decoding:** this is the main change. See the deep read below.
  - **`yolo_bbox2segment` class fix:** this function auto-labels segmentation data from box labels with SAM. SAM can drop boxes that produce empty masks. Before, the label file kept every original class next to the shorter list of masks, so **classes could shift onto the wrong polygons**. Classes are now indexed by the boxes SAM kept. If you built a seg dataset this way, re-generate it or spot-check images where SAM returned fewer masks than boxes.
  - **Tiled-inference merge (follow-up to the 8.4.204/205 tiling):** a fragment cut at a tile edge is restored only if no kept box *of the same class* covers half of it. Before, a large box of another class could hide a real small object.
  - **`convert_coco` collision check:** it now raises `FileExistsError` when two images in one COCO file map to the same label file (e.g. `frame.jpg` and `frame.png`). Before, their labels were silently appended into one file. LVIS conversion still appends.
  - **Colour-order fixes:**
    - SAM 3 semantic predictors (`SAM3SemanticPredictor`, `SAM3VideoSemanticPredictor`) now flip tensor inputs to BGR before building `Results`. Before, saved and plotted results from tensor inputs had red and blue swapped.
    - The `Annotator` now converts PIL inputs to the BGR buffer it uses for numpy inputs, instead of keeping the PIL channel order. Check any code that draws on PIL images and reads the result back.
  - **ONNX backend:** `ONNXBackend` takes a new `cuda_options` dict that is passed to the CUDA execution provider. The OCR recognizer now goes through it with `cudnn_conv_algo_search="HEURISTIC"`, rather than building its own session.
  - **Platform logging:** the first three `train_batch*.jpg` mosaics are uploaded as AVIF images (needs Pillow ≥ 11.3). A local `project=` path like `runs/exp` or `C:\work\exp` is no longer turned into a Platform project name. Only its last usable folder name is used.
- **AlbumentationsX 2.6.3** — [PyPI](https://pypi.org/project/albumentationsx/2.6.3/). Uploaded Nov 14, 05:20 UTC. Pins `albucore==0.3.9`.
  - **Breaking:** `A.ModeFilter` and `functional.mode_filter` are gone, with no deprecation step. The code has no stated reason. Pin 2.6.2 or remove the transform before upgrading.
  - **`ThinPlateSpline`:** the grid basis (kernel and affine terms for every pixel) depends only on the scaled image shape and the number of control points. It's now cached (`lru_cache(maxsize=2)`) when it fits in 8 MiB, so only the random weights are recomputed per call.
  - **`SaltAndPepper`:** below a sparsity threshold, it now samples pixel positions instead of building two full boolean masks. Volumes get their own 3D path.
  - **Tensor I/O:** Tensor↔NumPy conversion for images, masks and annotations now goes through albucore's new `tensor_bridge` layouts (`CHW`, `NCHW`, `CDHW`, …), replacing the hand-written permutes.

## Today's deep read

**Box-local mask decoding in Ultralytics 8.4.213** — [ultralytics 8.4.213 sdist on PyPI](https://pypi.org/project/ultralytics/8.4.213/#files) (`ultralytics/utils/ops.py`: `process_mask_local`; `models/yolo/segment/predict.py`: `construct_result`; `engine/results.py`: `Masks`; test: `tests/test_python.py::test_process_mask_local`).

- **What to read:**
  - **The switch in `construct_result`:** the dense path still runs when `N × H × W` is at most 2²⁵ pixels on CUDA or 2²² on CPU. Otherwise the local path runs. Worked examples:
    - At a 640×640 input, the CPU switches to box-local above 10 masks and CUDA above 81.
    - With `retina_masks=True` on 1920×1080 frames, the CPU switches above 2 masks and CUDA above 16.
  - **How `process_mask_local` works:** it computes, once per frame, the prototype coordinate that bilinear interpolation (`align_corners=False`) would sample for each output row and column. It clamps these inside the letterboxed area, so padding can't leak into mask edges.
  - **The batching loop:** boxes are sorted by area and grouped into padded batches. A batch stops growing when it would waste more than half its pixels or go over a 2²² interpolation budget. Each batch does the coefficient × prototype matmul, then interpolates columns and rows separately with `torch.lerp`, but only over the box's pixels.
  - **The `Masks` changes:** `Masks` can now hold `(rois, masks, shape)`. `.data` builds the dense `(N, H, W)` uint8 stack on first access. `__getitem__` stays box-local. `.xy`/`.xyn` run `findContours` on each crop and add the box offset back.
  - **The test's tolerance:** fewer than 1 in 10⁴ pixels may differ from `process_mask` and `process_mask_native`, from float rounding at mask edges.
- **Why it matters:** in crowded scenes (retail shelves, cells, aerial imagery, people in crowds) with full-resolution masks, the old path built an N × H × W tensor. That was often the slowest and most memory-hungry part of post-processing, more than the model itself. Now the cost scales with how much of the image the objects cover.
- **How it could apply to you:**
  - **Benchmark it:** time `postprocess` before and after upgrading on your densest validation images, with and without `retina_masks`, on CPU and GPU. The release ships no benchmark numbers, so measure your own.
  - **Avoid triggering the dense stack:** anything that reads `results[0].masks.data` (custom exporters, `masks.data.cpu().numpy()` dumps) still builds the full stack on first access. Use `.xy`/`.xyn`, or index first (`masks[keep]`), to keep the savings.
  - **Reuse the idea outside Ultralytics:** the same trick applies to any YOLACT-style prototype head, e.g. a C++/TensorRT post-processor. Crop the prototypes to the box, then upsample, instead of upsampling the whole frame and then cropping. Use the letterbox-aware clamping here as the reference for matching Python outputs pixel for pixel.
