## Today's deep read

**Upright images everywhere: EXIF orientation in Ultralytics 8.4.214** — [ultralytics 8.4.214 sdist on PyPI](https://pypi.org/project/ultralytics/8.4.214/#files) (`ultralytics/utils/patches.py`: `imread`, `_exif_transpose`; `data/dataset.py`: `DATASET_CACHE_VERSION`, `ClassificationDataset.imread`; `data/split_dota.py`).

- **What to read:**
  - **The new branch in `imread`:** an image counts as "stored" when the flag is `cv2.IMREAD_UNCHANGED` or the bytes at offset 8–11 are `WEBP`. Such images are decoded with `IMREAD_IGNORE_ORIENTATION` and then rotated by `_exif_transpose`. Other cases keep cv2's own handling.
  - **The comment it rests on:** cv2 leaves an image as stored with `IMREAD_UNCHANGED`, and leaves a WebP as stored with any flag before OpenCV 5.0.
  - **`_exif_transpose`:**
    - It reads EXIF tag 274 with Pillow and maps orientations 2–8 to a swap of the axes, then horizontal and/or vertical flips.
    - For PNG, it first walks the chunks looking for `eXIf`, so it doesn't make Pillow decode the whole file.
    - JPEG and WebP go through Pillow. TIFF is left to cv2, which already rotates it.
  - **Call sites:** classification datasets and DOTA splitting now go through the same `imread` as detection, which fixes the same bug there. `DATASET_CACHE_VERSION` moves to 1.0.13, so cached image shapes are rebuilt.
- **Why it matters:**
  - **Labels can be misaligned on WebP.** Phones and annotation tools often save rotated photos with an EXIF orientation flag. Annotators label the upright image their viewer shows. On OpenCV 4.x, a WebP like that was decoded sideways, so a box drawn for the upright frame landed on the wrong pixels. That is silent label noise in training and wrong coordinates at inference.
  - **The same was true for any pipeline reading with `IMREAD_UNCHANGED`,** e.g. to keep alpha or 16-bit depth, whatever the format.
- **How it could apply to you:**
  - **Check your data:** count images with orientation ≠ 1 per format, e.g. `PIL.Image.open(f).getexif().get(274, 1)`. If any are WebP, or you read with `IMREAD_UNCHANGED`, re-validate after upgrading: mAP on those images should improve, not move at random.
  - **Make sure serving matches training.** A C++/TensorRT or browser pre-processor has to apply the same orientation rule, or production images will be rotated differently from training images. The simplest fix is to bake the rotation into the pixels at ingest and strip the tag.
  - **Expect a slower first run:** the version bump forces a cache rescan.
