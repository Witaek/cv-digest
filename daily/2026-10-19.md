## TL;DR
- **Xiaomi-Lens-0 (4B, Apache-2.0)** is an open-weight MLLM that outputs boxes and pixel masks from a single backbone. It reaches 81.4% mean cIoU on RefCOCO/+/g segmentation, against 78.6% for Qwen3-VL-Seg-4B and 71.7% for SAM 3. It gets 63.9 F1 on COCO multi-instance grounding, against 60.6 for Grounding DINO. A new benchmark, LensBench, comes with it.
- **ExecuTorch now targets Cortex-M:** a µYOLO person detector runs at 24 ms per inference (12.7 FPS end to end, 128×128 input) on a 480 MHz Cortex-M85, using 254 KiB of RAM. It is INT8 through PT2E and CMSIS-NN, with an Ethos-U NPU partitioner.
- **Gemini 4 Argon ranks first in Roboflow's Vision Evals,** at 85.1% for object detection (field median 54.4%) and 87.5% overall. It takes 24–32 s and about $0.011 per detection sample, so it is a teacher for auto-labeling, not something to run at inference time.

## Top papers

- **Xiaomi-Lens-0: pixel-level grounding in a compact 4B MLLM** — [link](https://arxiv.org/abs/2610.23279), [code](https://github.com/SeerRay-Lab/Xiaomi-Lens-0), [weights](https://huggingface.co/SeerRay-Lab/Xiaomi-Lens-0), [LensBench](https://huggingface.co/datasets/SeerRay-Lab/LensBench).
  - **How it works:** the model starts from Qwen3.5-4B. Each generated `<|mask|>` token goes to a light decoder that combines the token's hidden state with one feature grid from the vision encoder. There is no separate SAM-style encoder and no multi-scale fusion. Mask tokens can also appear inside the reasoning trace, for example one mask per counted object.
  - **Referring expressions:** it averages 81.4% cIoU across the eight RefCOCO/+/g splits and leads on every split. RefCOCO+ testB is 76.3, against 70.8 for Qwen3-VL-Seg-4B. On box precision (Prec@0.5) it leads seven of eight splits, with RefCOCO val at 94.6 against 93.6 for Youtu-VL-4B.
  - **COCO multi-instance grounding:** it scores 63.9 F1 averaged over IoU 0.5–0.95, against 63.0 for GroundingPI and 60.6 for Grounding DINO. At IoU 0.5 alone, Grounding DINO is still ahead (81.4 vs 80.4).
  - **Reasoning and embodied segmentation:** ReasonSeg test is 68.0 gIoU, against 61.1 for InstructSAM. RoboRefIt testB cIoU is 81.2, against 55.5.
  - **LensBench:** 4,800 instructions over general, aerial, driving and panoramic images. Implicit wording is the weak spot: cIoU falls from 71.4 on explicit instructions to 54.7.
  - **Running it:** the repo has a Transformers inference script (bf16, FlashAttention-2) and a two-process vLLM setup, one process for text and one for masks. No latency figures are given. The weights are under an Xiaomi Corporation copyright notice, but the HF org is "SeerRay-Lab".

## Edge & deployment

- **ExecuTorch on Arm Cortex-M** — [blog](https://pytorch.org/blog/bringing-executorch-to-arm-cortex-m-cpus/), [docs](https://docs.pytorch.org/executorch/main/backends/arm-cortex-m/arm-cortex-m-overview.html), [person-detection example](https://github.com/pytorch/executorch/tree/main/examples/arm/person_detection_example_cortex_m). Posted Oct 15.
  - **What's new:** a Cortex-M backend with CMSIS-NN kernels, chosen at compile time for each ISA tier: scalar M0–M23, DSP M4–M35P, and Helium M55/M85.
  - **Toolchain:** quantization is INT8 through PT2E with a dedicated `CortexMQuantizer`. Memory is planned statically, with no heap. `EthosUPartitioner` sends supported ops to an Ethos-U55/65/85 NPU and runs the rest on the CPU.
  - **MLPerf Tiny models:** on one 400 MHz Cortex-M55 (Alif E8), MobileNet v1 0.25 for Visual Wake Words runs in 21.45 ms with 85 KiB peak RAM, and ResNet-8 in 15.29 ms with 55 KiB. These are the authors' own measurements, not an official MLPerf submission, and no accuracy is reported.
  - **µYOLO person detection:** on a Cortex-M85 (Renesas RA8D1), the INT8 model is 452 KiB with 254 KiB peak RAM, 24 ms per inference and 12.7 FPS end to end. Moving the hottest weights into DTCM and enabling the I-cache cut latency from 191 ms to 24 ms.
  - **Not yet supported:** mixed precision (A8W4, A16W8) is listed as future work.

## GPU / CUDA / PyTorch

- **Zephon: elastically deterministic data loading** — [blog](https://pytorch.org/blog/bringing-elastically-deterministic-data-loading-to-torchtitan-with-zephon/), [code](https://github.com/datologyai/zephon), [paper](https://arxiv.org/abs/2610.03087). Posted Oct 16, from DatologyAI.
  - **Why it matters:** with a standard loader, scores for the same 1B model varied by up to 0.82 points (DCLM Core) depending only on whether it trained on 8 or 64 GPUs. That is enough to swamp a data ablation.
  - **How it works:** data is split into fixed logical "lanes" instead of per-rank shards, and checkpoints use flush-and-replay. Global batches stay bit-identical when you resume on a different GPU count, and the spread drops to 0.05 points.
  - **Vision relevance:** it has been benchmarked on a vision-language pipeline with image decoding, where it keeps pace with Grain. The core library works without TorchTitan.

## Today's deep read

**Xiaomi-Lens-0** — [code + README results](https://github.com/SeerRay-Lab/Xiaomi-Lens-0), [paper](https://arxiv.org/abs/2610.23279).

- **What to read:**
  - **The mask decoder:** which encoder layer the "single feature grid" comes from (it is taken before spatial merging), and the output resolution of the masks. The answer decides boundary quality on small objects.
  - **The two-stage training:** stage 1 trains the decoder alone, then stage 2 fine-tunes every parameter. Check the training data mix on the project page.
  - **The COCO multi-instance table:** it beats Grounding DINO on the averaged F1 and at IoU 0.95, but not at IoU 0.5. Look at whether that comes from recall on crowded scenes or from tighter masks and boxes.
  - **LensBench implicit vs explicit:** the 16.7-point drop shows where reasoning-style queries still fail.
- **How it could apply to you:** a 4B model that returns boxes and masks from free-form text is a practical labeler for promptable segmentation. It covers cases SAM 3's concept prompts miss, such as "the second wedge from the left" or "what you'd squeeze on seafood".
  - **Labeling loop:** run it offline to produce boxes and masks for new classes or rare referring cases. Review them, then distill into your real-time detector or segmenter.
  - **Serving:** the vLLM split into a text server and a mask server is a ready template if you deploy it behind an annotation tool.
  - **Before relying on it:** measure latency per image yourself, since the repo gives none, and check mask quality at your image resolution.
