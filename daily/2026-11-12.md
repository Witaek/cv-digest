## TL;DR
- **Ultralytics 8.4.211 adds static INT8 export to ExecuTorch.** Use `format=executorch quantize=8 data=...`. It uses XNNPACK's per-channel symmetric INT8 and keeps the Detect head in float. It needs executorch ≥1.6.0, because earlier releases quantize the head concat anyway, and per the code comment that "zeroes the scores".
- **TensorRT INT8 now keeps more of the head in FP16 (8.4.211).** The exclusion now covers every bare conv and ConvTranspose in the last (head) module plus DFL, not only `.2/Conv` nodes. The rule also now works on `nms=True` exports. Re-export INT8 engines and re-check mAP and latency.
- **supervision 0.31.7: `MeanAveragePrecision` now matches pycocotools on size buckets and crowd targets.** A prediction's `data["area"]` no longer changes its size bucket. OBB mAP now uses the COCO crowd IoU: in the changelog's example, OBB mAP@50 goes from 0.333 to 1.0. Small, medium and large mAP numbers can change after you upgrade.

## Models & releases

- **Ultralytics 8.4.211** — [PyPI](https://pypi.org/project/ultralytics/8.4.211/). Uploaded Nov 11, 23:10 UTC.
  - **`cls_pw` class weighting for classification:** the inverse-frequency class weighting (`cls_pw`, default `0.0` = off) moved from the detection trainer to the base trainer. Classification training now uses it too, through `F.cross_entropy(weight=...)`. Counts are per source image, so each tiled source is counted once. YOLO-World and YOLOE still skip it, because their class channels are prompt positions.
  - **OCR on TensorRT:** the OCR solution accepts `recognizer="tensorrt"`. This builds PP-OCRv6 (the recognizer added in 8.4.210, covered yesterday) as an FP16 TensorRT engine, with dynamic batches of up to 8 crops, 48 px high and up to 3200 px wide. The engine is built once per TensorRT version and GPU architecture (about 30 s) and cached next to the ONNX file. The code comment says it reads "~40% faster than FP32". One TensorRT context is shared, so batches run one at a time under a lock.
  - **Breaking for float inputs:** NumPy float images passed to `predict` are now cast to `uint8` (the comment says "0-255 floats as uint8"). Before, they were kept as float32. **If you feed 0–1 normalized float arrays, they will now come out almost black.** Pass `uint8`, or scale by 255 first.
  - **Pose data:** the `tiger-pose.yaml` `flip_idx` was the identity. It now swaps left and right keypoints (`[0,1,2,3,7,6,5,4,10,11,8,9]`). Horizontal-flip augmentation used to train with mirrored legs left unswapped, so retrain models trained on that config.
  - **Speed and determinism:**
    - On CPU, SPPF now uses separable max pooling (1×k then k×1). CUDA and exports keep square pooling.
    - SAM's rotary encoding uses real arithmetic while under `torch.compile` (the comment: "torch.compile fuses real math but not complex math"). Eager mode keeps complex math.
    - A new `interpolate_bilinear` helper does bilinear resizes as matmuls on GPU when deterministic algorithms are on. This applies in the seg, semantic and depth losses and validators, and in the depth head.
  - **Other:** the TensorRT backend no longer requires the input to be named `images`. CoreML `quantize=8` for neural-network models now uses linear 8-bit weights; ML Programs keep k-means palettization.
- **supervision 0.31.7** — [PyPI](https://pypi.org/project/supervision/0.31.7/), [changelog](https://github.com/roboflow/supervision/blob/develop/docs/changelog.md). Uploaded Nov 11, 18:58 UTC.
  - **mAP size buckets:** a prediction's `data["area"]` used to replace its box or mask area. In the changelog's example, a medium false positive with `area=300` was counted as small, and small mAP for a perfect small prediction dropped from 1.0 to 0.5. Areas are now recomputed from the box or mask, as `pycocotools` does. Target areas are now kept in float64: float32 rounded `9216.0004` to `9216.0`, which put the target in both the medium and large buckets.
  - **OBB crowd IoU:** with `MetricTarget.ORIENTED_BOUNDING_BOXES`, targets with `iscrowd` now use intersection ÷ prediction area. Before, a prediction inside a crowd region counted as a false positive. In one axis-aligned scene, OBB mAP@50 went from 0.333 to 1.0, matching box mAP.
  - **Stricter inputs:**
    - `CSVSink` raises `ValueError` if an extra field uses a built-in column name such as `confidence` or `x_min`. Before, it silently wrote duplicate columns.
    - `KeyPoints` rejects boolean masks whose length is wrong. Before, it silently selected a subset.
    - `PolygonZone` no longer overflows when integer polygon coordinates reach their dtype limit.
  - **Labels and fallbacks:**
    - With `smart_position=True`, labels wider than the frame now stay at the left and top edges.
    - The OpenCV-free `contourArea` and `convertScaleAbs` fallbacks now give the same results as OpenCV: bit-identical areas, and float32 fused multiply-add rounding (e.g. `38 * 1.3 + 0.1` → 50, not 49).
  - **Exports:** `as_yolo` and `as_pascal_voc` now retry a failed hole-seam search on the traced contours. `as_coco` uses the box area for empty mask placeholders.
- **Release check (PyPI):** unchanged for RF-DETR 1.12.0, torch 2.15.0, torchvision 0.29.2, timm 1.0.31, transformers 5.22.2, SAHI 0.14.0, ONNX Runtime 1.31.1, ONNX 1.23.2, TensorRT 11.4.0.106, OpenVINO 2026.4.1, LiteRT 2.3.0, ExecuTorch 1.6.0, Triton 3.9.0, torchao 0.18.0, flash-attn 2.8.3.post2, Kornia 0.9.0, Model Optimizer 0.48.0, cuDNN 9.28.1.4, DALI 2.4.0, NNCF 3.4.0 and cuda-python 13.5.0. ## Edge & deployment

- **ExecuTorch static INT8 (Ultralytics 8.4.211):**
  - **How it works:** pass `format=executorch quantize=8` with calibration `data` (and optionally `fraction`). The model goes through `torch.export`, then `prepare_pt2e` with `XNNPACKQuantizer` (symmetric, per-channel). It is calibrated on the INT8 dataloader and then converted. The Detect head (and its subclasses) is left out of quantization. The code comment explains why: "one int8 scale over boxes and scores zeroes the scores".
  - **Requirement:** an assert enforces executorch ≥1.6.0.
  - **Gap:** no accuracy or latency figures are published. Measure on your own val set and target CPU against the FP32 `.pte`.
- **TensorRT INT8 head exclusions widened (8.4.211):**
  - **What changed:** in both the ModelOpt ONNX path and the native TensorRT builder path, layers now stay in FP16 if they are in the highest-numbered `/model.N/` module (the head) and are either a bare `Conv`/`ConvTranspose` outside a `Conv` block or part of `dfl`. The old pattern matched only `.2/Conv` names, so segmentation and pose heads with other output layers (e.g. ConvTranspose upsampling) were quantized.
  - **Linears:** `Gemm` layers stay INT8. The comment says keeping `Classify.linear` in float "measured no accuracy gain".
- **CoreML `quantize=8` (8.4.211):** for the legacy NeuralNetwork format (`format=mlmodel`), 8-bit weights now use linear quantization instead of k-means. Check accuracy if you still ship `.mlmodel`.

## Today's deep read

**INT8 for ExecuTorch, done the PT2E way** — [8.4.211 sdist on PyPI](https://pypi.org/project/ultralytics/8.4.211/#files) (`utils/export/executorch.py`, `engine/exporter.py`).

- **What to read:**
  - In `executorch.py`, the new `calibration_dataset` branch: `XNNPACKQuantizer().set_global(get_symmetric_quantization_config(is_per_channel=True))`, the `set_module_type(Detect, None)` exclusion, then `prepare_pt2e` → calibrate → `convert_pt2e` on the exported module.
  - In `exporter.py`, the `SPPF.export = True` switch. It keeps square pooling in the exported graph, because the new CPU path picks separable pooling based on the tensor's device, and that branch would otherwise leak into the trace.
- **Why it matters:** this is the third runtime in a week to keep the detector head out of INT8. Yesterday's 8.4.210 did it for TensorRT (RT-DETR attention) and LiteRT (head output convs). Today it's ExecuTorch and a wider TensorRT head exclusion. RF-DETR 1.12.0 did the same on ONNX/OpenVINO (covered Nov 7). Leaving the head in float is now the default way to quantize these detectors.
- **How it could apply to you:**
  - For Android or embedded Linux on XNNPACK, this is now a one-flag path to an INT8 `.pte`. Benchmark it against LiteRT INT8 for the same model, since both keep the head in float.
  - If you write your own PT2E quantization, copy the pattern: quantize the backbone and neck per-channel, and skip the head module with `set_module_type`. Then check the score distribution, not just mAP: collapsed scores show up as near-zero detections, not a small mAP drop.
  - Before upgrading, check any code that passes float images to `predict`. The new `uint8` cast in `loaders.py` breaks 0–1 normalized inputs without raising an error.
